Chapter One

What is a node, really?

Forget the word "node" for a second. Think of it as one instruction you're giving the software — "do this to the image." Nothing more mysterious than that.

The node tree, then, is just a flowchart. It shows the order you want those instructions carried out in. Layer-based editors like Premiere or Final Cut stack effects invisibly inside a clip's properties panel. Resolve instead lays every instruction out on a little map you can see, rearrange, and switch on or off — which is exactly why it feels unfamiliar at first, and exactly why it becomes so powerful once you're used to it.

💡
Green dots = input and outputEvery node tree starts with a green dot on the left (the original, ungraded clip as it arrives from your timeline) and ends with a green dot on the right (the final graded image that gets sent back). Everything in between is where you do the actual work.

Chapter Two

The simplest tree you can build

A brand-new clip on the color page already has this: source in, one node, output out. Select that node and add some contrast, and you've made your first grade.

That single node has two kinds of connectors, or "inputs." The green ones on its left and right carry the actual RGB image — the picture itself. There's also a set of blue ones, which carry something different: transparency information. We'll come back to those blue connectors in a few chapters, when they finally get interesting.

💡
RGBRed, Green, Blue — the three colors every pixel on your screen is built from. When people say a connector "carries the RGB," they mean it's passing along the actual picture, not just some side information about it.

Chapter Three

Why one big node is a bad idea

You could add contrast, saturation, and warmth all on that one node. Resolve won't stop you. But try to check your work afterward, and you'll hit a wall: you can turn the whole node off with ⌘D / Ctrl+D, but you can't isolate just the contrast, or just the saturation. To see one adjustment on its own, you'd have to undo and redo each one by hand — which gets old fast.

The fix is simple: split adjustments across separate nodes. Add a node for contrast. Add another for saturation. Add a third for warmth. Now each one can be switched on and off independently, and you can actually see what each instruction is doing to your image.

ONE ADJUSTMENT PER NODE
SRC
Contrastnode 1
Saturationnode 2
Warmnode 3
OUT

Three small, labeled nodes beat one crowded one — each can be toggled, inspected, and reordered on its own.

💡
Node labelsRight-click any node and choose "Node Label" to name it (or assign a keyboard shortcut for it under Keyboard Customization). Do this every time. A tree full of unlabeled boxes is unreadable a week later — even to the person who built it.

Chapter Four

Order changes everything

Here's the idea that trips up almost everyone coming from a layer-based editor: a serial node tree runs top to bottom, left to right — swap two nodes, and you can get a completely different image, even though neither node itself changed.

Take two instructions: "remove all color" and "make the image green." Depending which one runs first, you land in a totally different place.

DESATURATE → GREEN TINT
Remove color→Add green
Result: green cast
GREEN TINT → DESATURATE
Add green→Remove color
Result: no color at all

In the first order, the image is grayscale by the time the green is added, so the green cast survives — you end up with a greenish black-and-white look. In the second order, the green gets added first, and then the desaturation step wipes out all color, green included. Same two nodes. Same two adjustments. Opposite results, purely because of the order they're connected in.

🔧 How to reorder

Hover the right edge of any connector until it turns blue, then click to disconnect it. Drag from a node's output back to a different node's input to rewire the chain. It takes a few tries the first time — after that, it's second nature.

Chapter Five

Parallel nodes: same input, no interference

Serial nodes are what you'll use 90% of the time. But sometimes you want several adjustments that don't feed into each other at all — each one working from the same untouched starting image, independently.

That's a parallel node. Add one (right-click → Add Node → Add Parallel, or ⌥P / Alt+P) and Resolve splits your signal, feeding an identical copy of the image to two or more nodes at once. A dedicated node called the parallel mixer then blends all of their outputs back together into one image.

ONE SIGNAL, SEVERAL INDEPENDENT NODES, ONE BLEND
SRC
Window Ared tint
Window Bblue tint
Parallel
Mixerblends all
OUT

Grade Window A red and Window B blue — neither branch sees the other's changes. Where the two windows overlap, the mixer blends both colors together. The order the branches connect into the mixer doesn't matter; the result is identical either way.

This is the tool for grading several isolated regions of a shot at once without one adjustment's math bleeding into the next one's starting point.

Chapter Six

Layer nodes: same shape, opposite rule

A layer node (⌥L / Alt+L) looks almost identical to a parallel one on the node tree — same fan-out, same mixer at the end. But it works completely differently: instead of blending branches together, a layer mixer stacks them, one on top of another, the way layers stack in Photoshop.

💡
Why this mattersWith a stack, whichever layer is "on top" wins wherever it's visible, and everything underneath it only shows through the gaps — a mask, a key, a window. With a blend (parallel), every branch always contributes something, everywhere.

Here's the part that catches everyone out. You'd assume the node wired into the mixer's top input ends up as the top layer. It's the opposite: in Resolve's layer mixer, the node connected to the bottom input becomes the top layer of the stack. There's no elegant explanation for it — it's just the convention, and it's worth memorizing precisely because it's so unintuitive.

MIXER INPUTS (top → bottom)
Node A
Node B
⇄
VISUAL STACK (top → bottom)
Node B
Node A

So if your top layer desaturates the whole frame and it's covering everything, that's expected — it's sitting on top of the stack even though it looks "first" going into the mixer. Add a window or a key to that top node, and now it only covers part of the frame, letting the layer beneath show through everywhere else. Swap the connection order into the mixer, and you'll swap which layer sits on top.

💡
KeyA "key" isolates part of an image by color or brightness rather than by shape — for example, selecting only the blue pixels in a shot. A window, by contrast, isolates by shape (a circle, a box, a custom curve) regardless of color.

Chapter Seven

Outside nodes: flipping the mask

Say you've put a window around a face to brighten it. Now you also want to darken everything except the face — the walls, the background, the rest of the frame. Re-drawing a second window for "everything but the face" would be painful, and it would break the moment you nudge the first window even slightly.

An outside node (⌥O / Alt+O) solves this automatically. Add one after a node that already has a window or key on it, and Resolve draws a dashed blue line between the two — the alpha connection we mentioned back in chapter two, finally doing something. The outside node inherits the exact same window, but inverts it, so your adjustments land everywhere the original window doesn't cover.

💡
Alpha channelAlongside a picture's color (RGB), Resolve tracks a fourth, invisible channel called alpha — essentially a black-and-white map of "how much does this adjustment apply here." A window or key is really just a shape drawn onto that alpha map. The blue connectors carry this map between nodes; the green ones carry the actual image.
A MASK, AND ITS AUTOMATIC OPPOSITE
Original window
brightens inside the circle
Outside node
darkens everything else

Move or reshape the original window, and the outside node's inverted mask updates automatically — they're permanently linked through that dashed alpha connection.

Chapter Eight

The cheatsheet

Everything above, condensed. Bookmark this section — it's built to be scanned, not read.

🖥️ Shortcuts below are shown as Option (Mac). On Windows, swap Option for Alt and ⌘ for Ctrl throughout.

Serial

⌥S

Runs one after another, left to right. The default node type, and the one you'll reach for most.

  • Order changes the result
  • One instruction per node — keep it isolated and toggleable
  • Toggle a node on/off: ⌘D

Parallel

⌥P

Splits one signal to several nodes at once, then blends every output together via a parallel mixer.

  • Branches never see each other's changes
  • Connection order into the mixer doesn't matter
  • Good for grading several isolated regions together

Layer

⌥L

Looks like Parallel, but stacks branches instead of blending them — like layers in Photoshop.

  • Order matters — connection order sets stacking order
  • ⚠️ Bottom mixer input = top of the visual stack
  • A window/key on the top layer reveals the layer below through the gap

Outside

⌥O

Auto-inverts the mask (window or key) from the node before it — a dashed blue alpha link ties the two together.

  • Adjustments apply everywhere the original mask doesn't
  • Reshaping the original mask updates this node automatically
  • No need to redraw a second, opposite mask by hand

📌 The one habit that saves every future headache

Label every node the moment you create it. It costs three seconds. A tree of six unlabeled gray boxes tells you nothing — the same tree with "Contrast," "Skin Tone," "Sky Window," and "Final Look" tells you everything, weeks later, at a glance.

Recap

Four node types. One flowchart.

Serial for step-by-step instructions where order matters. Parallel when you want isolated adjustments blended together. Layer when you want them stacked instead. Outside when you want the exact opposite of a mask you've already drawn. That's the whole system — everything else in Resolve's node tree builds on these four.
