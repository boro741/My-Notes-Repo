The Big Pictureबड़ी तस्वीर

Spring Boot is not a replacement for Spring. It sits on top of Spring Framework and removes the boring setup. You add dependencies, and Boot decides what to configure.

Think of it in four layers: your code on top, Boot's "magic" below it, the Spring Framework engine under that, and the JVM at the bottom.

सीधी बात: Spring Framework एक बड़ा toolbox है, पर उसे set up करना थका देने वाला था। Spring Boot ने उस toolbox के ऊपर एक smart assistant बिठा दिया — जो आपकी dependencies देखकर खुद decide करता है कि क्या configure करना है।

2
What Happens at StartupApp शुरू होते ही क्या होता है

Everything begins with one line:

@SpringBootApplication
public class DemoApp {
  public static void main(String[] args) {
    SpringApplication.run(DemoApp.class, args);  // ← the whole show starts here
  }
}

run() follows a fixed pipeline. Follow the numbers in the diagram: the snake path goes left → right, then back right → left.

The most important step is refresh(). This is where Spring scans your classes, applies auto-configuration, and builds every singleton bean. If something is wrong (a missing bean, a circular dependency), this is where your app crashes.

समझो ऐसे: जैसे आप दुकान खोलते हो — पहले बोर्ड लगाना (Bootstrap), फिर licence और register देखना (Environment), फिर दुकान का ढाँचा बनाना (Context), सामान सजाना (refresh), दरवाज़ा खोलना (Tomcat) और आख़िर में "Open" का बोर्ड पलटना (Runners)।

3
Auto-Configurationजादू का असली राज़

@SpringBootApplication is three annotations in one: @Configuration + @ComponentScan + @EnableAutoConfiguration. The last one is the star.

Spring Boot ships a list of 150+ candidate configuration classes inside META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports. Each one is guarded by conditions. Only the ones whose conditions pass are applied.

Here is how a typical auto-configuration looks inside Boot (simplified):

@AutoConfiguration
@ConditionalOnClass(DataSource.class)           // only if JDBC is on the classpath
public class DataSourceAutoConfiguration {

  @Bean
  @ConditionalOnMissingBean                       // back off if user defined one
  public DataSource dataSource(DataSourceProperties props) {
    return props.initializeDataSourceBuilder().build();
  }
}
Pro tip: run your app with --debug to print the Conditions Evaluation Report. It lists every auto-config that matched, and every one that did not, with the reason.
आसान भाषा में: Boot आपकी classpath देखता है। Web starter मिला? Tomcat और MVC लगा दो। Database jar नहीं मिला? वो config छोड़ दो। और अगर आपने खुद का bean बना दिया, तो Boot पीछे हट जाता है — आपका बनाया हुआ हमेशा जीतता है।

4
Starters & the Bean ContainerBeans का घर

Starters are just dependency bundles. Add spring-boot-starter-web and you get Spring MVC, Jackson, Tomcat and validation, all with compatible versions. No version hunting.

starter-web

MVC + Tomcat + Jackson for REST APIs.

starter-data-jpa

Hibernate + Spring Data + HikariCP pool.

starter-security

Filter chain + auth defaults, locked by default.

starter-test

JUnit, Mockito, AssertJ and MockMvc together.

All objects that Spring manages are called beans. The ApplicationContext creates them, wires them together (dependency injection), and destroys them. Each bean follows this life:

Instantiate➜ Inject deps (DI)➜ Aware callbacks➜ @PostConstruct➜ Ready to use ✅➜ @PreDestroy

Prefer constructor injection. It makes dependencies explicit, and your classes are easy to test without Spring.

@Service
public class OrderService {
  private final OrderRepository repo;

  public OrderService(OrderRepository repo) {   // Spring injects this
    this.repo = repo;
  }
}
Bean मतलब वो object जिसे Spring संभालता है। आप new नहीं करते — Spring उसे बनाता है, ज़रूरी चीज़ें जोड़ता है (DI), और काम ख़त्म होने पर हटा भी देता है। Starter मतलब एक ही dependency में पूरा सामान — version की टेंशन ख़त्म!

5
Life of a Web RequestRequest का पूरा सफ़र

Once the app is running, every HTTP call goes through the same road. The hero here is the DispatcherServlet, the front controller of Spring MVC.

Request का सफ़र: Browser → Tomcat → Filters → DispatcherServlet → Controller → Service → DB, और फिर वही रास्ता वापस JSON बनकर। DispatcherServlet यहाँ receptionist है — हर request को सही कमरे (controller) तक पहुँचाता है।

6
Configuration & ActuatorSettings और निगरानी

Boot reads settings from many places. When the same key appears twice, the higher source wins (simplified order):

  1. Command-line args — --server.port=9090
  2. OS environment variables — SERVER_PORT=9090
  3. Profile files — application-prod.yml
  4. Default file — application.yml
  5. Built-in defaults — port 8080 and friends

Actuator adds production-ready endpoints with almost no work: /actuator/health, /actuator/metrics, /actuator/env. Expose only what you need, and secure them.

याद रखो: जो source ऊपर है वो नीचे वाले को override कर देता है। इसीलिए production में हम environment variables से password और port बदलते हैं, code बदले बिना।
