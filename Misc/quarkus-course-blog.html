Quarkus Kya Hai?

Quarkus ek Java toolkit hai jo cloud ke liye banaya gaya hai. Ye jaldi start hota hai aur kam memory khata hai. Isiliye "Supersonic Subatomic".
Pehle ek chhota idea: toolkit matlab tools ka dabba. Quarkus me kuch cheezein framework jaisi hain, kuch server jaisi. Isliye sab usse "Java toolkit" bolte hain.

Supersonic = Speed 🚀

  • Developer ke liye fast: code badlo, Quarkus apne aap reload ho jata hai. Turant test karo.
  • App ke liye fast: app start hone ke baad pehla response bahut jaldi deta hai.

Subatomic = Chhota size ⚛️

Atom bahut chhota hota hai, subatomic usse bhi chhota. Quarkus app ka size aur memory dono kam hote hain.

Numbers dekho (race!)

Simple REST app ko start karke pehle response tak ka time:

Startup Race
Traditional Java framework
~4 sec
Quarkus + HotSpot (JVM)
< 1 sec
Quarkus + GraalVM (native)
0.01 sec

Bars ki speed asli time ke hisaab se hai. Native wala to blink karte hi khatam!

REST + database wali bigger app me: traditional ~10 sec, Quarkus JVM ~4 guna fast, native sirf 0.05 sec.

Memory ka hisaab

Memory Footprint

Pure process ki RAM (sirf JVM ki nahi):

140 MB
Quarkus + JVM

Quarkus + native
< 20 MB

REST + DB wali app: 220 MB ➜ aadha (Quarkus JVM) ➜ 40 MB se kam (native).

Official line ko todke samjhte hain

Jargon Buster

"Quarkus is a Kubernetes Native Java stack tailored for OpenJDK HotSpot and GraalVM, crafted from the best of breed Java libraries and standards."

Kubernetes Native
Kubernetes ek tool hai jo bahut saare containers ko manage karta hai. "Native" matlab Quarkus ko isi duniya ko soch ke banaya gaya hai. Is course me Kubernetes use nahi hoga, par Docker me jo hum karenge wahi Kubernetes me bhi aasaan hai.
HotSpot
Normal JVM ka naam. Quarkus pehle HotSpot ke liye optimize hai.
GraalVM
Ek special tool jo Java code ko seedha machine ke samajhne wale binary me badal deta hai. Ye "ek step aage" hai.
Best of breed libraries
Quarkus naye sire se sab kuch nahi banata. Purani, mashhoor Java libraries use karta hai. Agar tum unhe jante ho, Quarkus aasaan lagega.
Standards
Java ke official rules jaise MicroProfile, JPA.

Aur kuch jaanne layak baatein

  • 2018 ke end me bana. Open source hai. Red Hat company iske peeche hai.
  • Sirf microservices ke liye nahi. Har tarah ki app ke liye theek hai.
  • Core bahut chhota hai. Baaki sab extension hai. Matlab sirf wahi lo jo chahiye.
Extension kya hota hai?

Mobile ke apps jaise. Phone me sirf wahi app daalo jo kaam aaye. Quarkus me Hibernate, Kafka, RESTEasy, Vert.x, Prometheus, Kubernetes, sab extension hain. Team ke bhi hain, community ke bhi, aur tum apna bhi bana sakte ho.

Quarkus ka asli kaam: Java ko cloud tak lana

Kal vs Aaj
Pehle (Kal)Ab (Aaj, cloud)
MachineBade serversChhoti machines, kai cores
AppEk bada monolithSainkdon microservices
ChalnaSaal bhar 24/7, startup time ka tension nahiJaldi start, jaldi stop, idhar-udhar move

Problem ye thi ki JVM bhaari hai. Ek server pe Node.js ya Go ke muqable Java ke kam apps aate the. Quarkus ka goal hai wohi density (ek server pe zyada apps) Java me wapas lana.

Yaad rakho Ye sirf cloud ke liye nahi. Jo cloud me achha hai, wo tumhare laptop aur apne data center me bhi achha hai.

BOM kya hai?

BOM = Bill of Materials. Ek list jisme sab Quarkus extensions ke sahi versions likhe hain. Isse har dependency ka version tumhe khud nahi likhna padta. Bas BOM daalo, aur extensions add karo.

Generated pom.xml me ye dependencies aati hain: quarkus-resteasy (REST, JAX-RS), quarkus-resteasy-jsonb (JSON), quarkus-arc (injection, aage dekhenge), aur test scope me quarkus-junit5 aur rest-assured.

REST Endpoint & Bean Injection

Ek Book class banao, endpoint se JSON me books wapas bhejo. Phir code ko saaf karne ke liye BookRepository alag karo aur @Inject se jodo.

JAX-RS kya hai?

Jargon Buster
REST endpoint
Ek URL jise koi bhi call kare to wo data wapas deta hai. Jaise /api/books.
JAX-RS
Java ke REST banane ke rules (specification). Bas rule-book hai.
RESTEasy
Un rules ko implement karne wali library. Quarkus me wohi use hoti hai.
JSON-B
Java object ko JSON text me badalne wala jaadugar. Tumhe kuch nahi karna, extension add karo bas.
AnnotationMatlab
@GET, @POST, @PUT, @DELETEKaunse HTTP verb pe ye method chalega
@PathURL ka raasta. Class pe main path, method pe sub path.
@PathParamURL ke beech ka variable, jaise /api/books/123 me 123
@ProducesJawab kis format me denge (JSON, text)
@ConsumesKis format ka input lenge (POST ke time kaam aata hai)

Step 3: Code saaf karo (Injection)

Abhi BookResource bahut kuch kar raha hai: HTTP bhi, books ka data bhi. Isko do hisso me todte hain. Ise bolte hain separation of concerns (har class ka ek hi kaam).

Jargon Buster
Bean
Ek normal Java object jise Quarkus (CDI) manage karta hai. Banana, dena, hatana, sab wohi dekhta hai.
Dependency Injection (DI)
Jis class ko kisi dusre object ki zaroorat hai, wo new nahi karti. Quarkus bana ke de deta hai. Chai ki tapri jaisa: tum cup aur patti nahi laate, chai wala sab ready rakhta hai, tum bas chai piyo.
CDI
Contexts and Dependency Injection. Java ka standard jo DI aur bean ka lifetime sambhalta hai. Quarkus me iska implementation ArC hai (quarkus-arc extension).
@Inject
Bolta hai "mujhe ye bean chahiye, de do".
@ApplicationScoped
Poori app me is bean ka sirf ek object banega.
@RequestScoped
Har HTTP request pe naya object banega.
Repository ke liye ApplicationScoped kyun? Is class ke andar koi data store nahi hota. Sirf methods hain. Isliye ek hi object kaafi hai. Session ya request scope ki zaroorat nahi.
BookRepository.java (naya) 
@ApplicationScoped
public class BookRepository {

    public List<Book> getAllBooks() { /* wahi 4 books jo pehle the */ }

    public Optional<Book> getBook(Integer id) {
        return getAllBooks().stream().filter(b -> b.id.equals(id)).findFirst();
    }
}
BookResource.java (refactored) 
@Path("/api/books")
@Produces(MediaType.APPLICATION_JSON)
public class BookResource {

    @Inject BookRepository repository;
    @Inject Logger logger;               // org.jboss.logging.Logger

    @GET
    public List<Book> getAllBooks() {
        logger.info("Returns all books");
        return repository.getAllBooks();
    }

    @GET @Path("/count") @Produces(MediaType.TEXT_PLAIN)
    public Integer countAllBooks() {
        logger.info("Returns the number of books");
        return repository.getAllBooks().size();
    }

    @GET @Path("/{id}")
    public Optional<Book> getBook(@PathParam("id") Integer id) {
        logger.info("Returns a single book with id " + id);
        return repository.getBook(id);
    }
}

Testing the Endpoint

Test class pe @QuarkusTest lagao. RestAssured se endpoint ko "given / when / then" me test karo. mvn test chalao.
Hum sirf endpoint test karenge. Andar ka Book ya Repository alag nahi. Ise bolte hain black box testing: andar kya hai pata nahi, sirf bahar ka behaviour dekhna hai.
Jargon Buster
Unit test
Ek class akeli test karo. Baaki cheezein mock (nakli) karo.
Integration test
Kai classes saath me test karo, container ko chalta rakh ke. Quarkus ke tests aise hi hain. Isliye injection ko mock nahi karna padta.
@QuarkusTest
Ek JUnit runner. Test se pehle Quarkus start (port 8081) karta hai, tests chalata hai, phir band kar deta hai.
RestAssured
REST API test karne ki library. Padhne me English jaisi lagti hai.
Notes
  • Quarkus JUnit 5 support karta hai. JUnit 4 nahi. TestNG ka support nahi hai.
  • JUnit aur RestAssured bhi extensions hain, aur test scope me hain.

Test code

BookResourceTest.java 
@QuarkusTest
public class BookResourceTest {

    @Test
    void shouldGetAllBooks() {
        given().header("Accept", MediaType.APPLICATION_JSON)
        .when().get("/api/books")
        .then().statusCode(200)
               .body("size()", is(4));
    }

    @Test
    void shouldCountAllBooks() {
        given().header("Accept", MediaType.TEXT_PLAIN)
        .when().get("/api/books/count")
        .then().statusCode(200)
               .body(is("4"));            // text hai, number nahi
    }

    @Test
    void shouldGetABook() {
        given().header("Accept", MediaType.APPLICATION_JSON)
               .pathParam("id", 1)
        .when().get("/api/books/{id}")
        .then().statusCode(200)
               .body("title", is("Understanding Quarkus"))
               .body("author", is("Antonio"))
               .body("yearOfPublication", is(2020))
               .body("genre", is("IT"));
    }
}
Given / When / Then Given: pehle se kya set hai (header, parameter). When: kya karte hain (GET). Then: kya hona chahiye (status 200, body).
Instructor ki galtiyan (aap bhi karoge!)
  • Count test pehle fail hua kyunki wo string "4" hai, number 4 nahi.
  • Single book test me pathParam("id", 1) dena bhool gaye. Phir pass hua.
Chalao 
mvn test

Logs me dekhna: Quarkus start hota hai, har test chalta hai, Quarkus band hota hai. IDE me bhi green button se test chal jata hai.

Apni app ki config

MicroProfile Config

@ConfigProperty

Dekho kya hua

Executable JAR & Native Executable

mvn package se executable JAR milta hai. GraalVM ke saath -Pnative se native binary milta hai jo 0.02 sec me start hota hai.

Executable JAR

Normal JAR me sirf tumhara code hota hai. Quarkus ka executable JAR me tumhara code + dependencies + runtime sab hota hai. Isliye java -jar se seedha chal jata hai.

TypeKya haiCommand
JAR (default, pehle Fast-JAR)Code, libs alag-alag, plus index jo class dhundhna fast karta haimvn package
Legacy JARBina index wala, thoda slow-Dquarkus.package.type=legacy-jar
Uber-JAR (Fat-JAR)Hazaaron classes ek hi bade JAR me (~11 MB yahan)-Dquarkus.package.type=uber-jar
Confusion se bacho Quarkus 1.12 se pehle default "JAR" ko fast-jar bolte the aur legacy ko "jar". Purani docs padh rahe ho to naam ka dhyaan rakho.
Classpath scanning kya hai?

JVM ko ek class chahiye. Wo saare JAR files me dhundhta hai. Index ek "phone directory" hai jo seedha bata deta hai kaunse JAR me hai. Isliye fast.

Build & run 
mvn package -DskipTests
java -jar target/quarkus-app/quarkus-run.jar          # default JAR

mvn package -DskipTests -Dquarkus.package.type=uber-jar
java -jar target/rest-book-1.0-SNAPSHOT-runner.jar    # Uber-JAR

java -Dquarkus.banner.enabled=false -jar target/quarkus-app/quarkus-run.jar

quarkus-app folder me kya hai? app/ tumhara code, lib/boot Quarkus ka core, lib/main external dependencies, quarkus/ generated bytecode aur index.

Profile yaad hai? JAR chalate hi %prod profile active hota hai. Isiliye books.genre ab information technology aayega.

Jargon Buster
Native image
GraalVM ke saath aane wala tool jo tumhari app ko tumhare OS ke binary me badalta hai.
Closed world assumption
GraalVM sirf wahi code rakhta hai jo app sach me use karti hai. Baaki phenk deta hai, kisi class ka unused method bhi. Isi se binary chhota bana rehta hai. Pack karte waqt sirf kaam ka saaman rakhna, jaise trip pe sirf zaroori kapde.
Ahead-of-Time (AOT) compilation
Code ko pehle hi (build time pe) compile kar lena, run time pe nahi. Pre-cooked khana jaisa: dabba kholo aur ready.

}
Native test chalao 
mvn verify -Pnative       # mvn test sirf JVM tests chalata hai
  • @QuarkusTest = JVM mode. @NativeImageTest = native mode.
  • Native test verify goal me chalta hai (failsafe plugin se).
  • Demo me JVM test pass hua par native fail, kyunki test me genre IT tha aur prod me information technology. Fix: native test me wo test override karo aur "information technology" expect karo.

Docker Containers

Ek extension add karo, -Dquarkus.container.image.build=true do aur Docker image ban jati hai. Native ke liye Linux binary banana padta hai, Quarkus Docker se ye bhi kar deta hai.

JAR se Docker image

Quarkus ke 2 extensions hain: Docker (Docker chahiye) aur Jib (bina Docker ke image bana sakta hai, CI/CD me kaam aata hai). Hum Docker wala use karenge.

Uber-JAR ke liye Dockerfile kyun nahi? Uber-JAR ek bada blob hai. Code me chhota change karo to pura blob dobara banana padta hai. JAR aur legacy JAR me libs alag hain, isliye Docker layers cache hoti hain aur build fast hota hai.
Jargon Buster
Docker image
App ka ready-to-run packet: OS ka chhota hissa + Java + tumhara code.
Container
Image ko chalane par jo banta hai. Image recipe hai, container bana hua khana.
Dockerfile
Image banane ke steps ki file. Quarkus ne Dockerfile.jvm aur Dockerfile.native pehle hi bana ke diye hain.
UBI minimal
Red Hat ka bahut halka Linux (Universal Base Image). Bas zaroori cheezein.

Dockerfile.jvm ye karta hai: UBI minimal lo ➜ Java 11 install karo ➜ target/quarkus-app ko /deployments me copy karo ➜ port 8080 expose karo ➜ run script chalao.

Extension jodo & image banao 
mvn quarkus:add-extension -Dextensions="container-image-docker"

mvn package -Dquarkus.container.image.build=true \
            -Dquarkus.container.image.tag=jvm

docker image ls                             # ~500 MB (Linux + JVM + code)
docker run -p 8080:8080 agoncal/rest-book:jvm
curl localhost:8080/api/books
Error aaye to Docker extension ko Docker chahiye. Docker Desktop start karo.
Image naam agoncal/rest-book:1.0-SNAPSHOT default hota hai. quarkus.container.image.tag se tag badal sakte ho. Yahan jvm rakha taki baad me native alag dikhe.

Linux native binary ka jugaad

Problem: Mac pe bana binary Mac ke liye hai. Container ke andar Linux hai. Wo chalega nahi.

Quarkus ka trick Quarkus Docker se ek Linux image khinchta hai jisme GraalVM aur native-image installed hain, aur usme Linux binary build karta hai. Tumhe Linux machine nahi chahiye.
Native Docker image 
mvn package -Dquarkus.package.type=native \
            -Dquarkus.native.container-build=true \
            -Dquarkus.container.image.build=true \
            -Dquarkus.container.image.tag=native

docker run -p 8080:8080 agoncal/rest-book:native
Instructor ne ye galti ki native.container-build=true bhoolne pe build fail hua ("binary Linux ka nahi hai"). Dekho: build ke baad bhi target/ ka binary Mac pe nahi chalega, kyunki wo Linux ka hai. Wo sirf container me chalega.

Dockerfile.native me Java install hi nahi hota, kyunki 30 MB binary me sab kuch hai. Image sirf 135 MB (UBI + binary) hai, JVM image ~500 MB ki thi.
