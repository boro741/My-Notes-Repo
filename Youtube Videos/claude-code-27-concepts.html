Part One

The foundations

Before touching a single command, you need the mental model. These eight ideas are the entire skeleton — everything else in this piece just adds muscle onto it.

01

What is Claude Code?

Chatbots like ChatGPT or regular Claude can only talk — they reply with advice. Claude Code can actually take action: create files, build websites, install packages, and run repetitive tasks, straight from a plain-English conversation.

ExampleYou type "Build me a to-do list app" — and real files appear on your computer, not just instructions for building one.
02

The terminal

Claude Code lives in the terminal, not a browser — that black screen with white text. It looks cryptic, but it's just another way to talk to your computer: you type instead of click. With Claude Code you barely need to know any commands yourself.

ExampleType claude to open it, press Control + C twice to close it, and type /clear to wipe its memory.
03

Prompts

A prompt is simply what you type to tell Claude Code what to do — no special syntax, no code. Just describe what you want. The more specific you are, the better the result.

ExampleInstead of "build me a website," try: "Build a one-page landing page for a consulting business, green color scheme, a contact form, and three cards explaining our services."
04

Permissions

Claude Code can create, edit, and delete real files, so by default it asks approval before anything significant. Pre-approve the safe stuff in a settings file so you're not clicking "yes" every ten seconds.

Example"Add the common safe permissions to my settings — reading files, running tests, git operations, starting the dev server — and show me before you save it."
05

Tool use

What makes Claude Code more powerful than a plain chatbot is that it has tools — built-in abilities like Read (look at files), Write (create files), and Bash (run commands). You don't pick the tool; you describe the goal and Claude picks automatically.

ExampleAsk "list the files in this folder" and Claude quietly runs the ls command behind the scenes.
06

The context window

This is Claude's short-term memory — every message, file, and reply currently "in view." It has a limit, and once it fills up, Claude starts forgetting earlier details. That's called context rot.

ExampleWatch the green bar at the bottom of the terminal — it shows you how full your context window is getting.
07

Conversation history

Every session is automatically saved. Close your laptop, come back tomorrow, and you don't have to start from zero.

ExampleType claude --resume to jump straight back into your most recent conversation, with the same context intact.
08

Token usage

Claude Code costs money, billed in tokens — roughly ¾ of a word each, so 1,000 tokens ≈ 750 words. Every prompt, reply, and file read spends tokens, and pricier models cost more per token.

ExampleType /cost or /stats any time to see exactly how many tokens you've burned through this session.

💡 Quick tip: what's "context rot"?

Think of the context window like a desk. The more papers you pile on it — messages, files, replies — the harder it is to find anything, and eventually the oldest papers fall off the back. That's context rot: Claude's answers get worse because the early details have quietly slid off the desk.

Part Two

Make it yours

Out of the box, Claude Code is a blank slate — it has to guess how you like things done. These six concepts are how you turn it into something that actually works your way.

09

CLAUDE.md

A markdown file in your project where you write your rules, preferences, and project structure. Claude reads it, line by line, at the start of every single session — arguably the most important file you'll create.

Example"We use TypeScript. Always write in our brand voice. Never use em dashes." Write it once, and every future conversation follows it.
10

Memory (auto-memory)

CLAUDE.md is memory you write by hand. Auto-memory is different — Claude quietly notices patterns in how you work and saves them so it remembers across sessions, not just within one chat. You can ask it to add, remove, or review what it's stored.

ExampleAlways build in JavaScript? Eventually Claude just assumes it, without being told again.
11

Compact context

When the context window gets close to full (around 85–95%), Claude automatically summarizes the key info and clears the noise. You can also trigger this yourself, mid-session.

ExampleType /compact keep info about API calls to compact manually while protecting specific details.
12

Models

"Claude Code" isn't one model — it's a family, each with different speed, intelligence, and cost. Match the model to the size of the task.

ExampleType /model mid-conversation to switch — Sonnet for most of your session, Opus only for the hardest part.
13

Denying file access

Not every file should be visible — some are huge and waste context, some hold secrets like API keys, some are just irrelevant. A deny list makes files completely invisible: Claude can't discover, search, or read them, even if you ask directly.

ExampleDeny access to .env, your /secrets folder, and any credentials files.
14

Flags

Options you attach when launching Claude Code, customizing that session's behavior before it even starts.

Exampleclaude --model opus picks your model upfront; --verbose shows more detail on everything Claude does.

The three levels of permission, side by side

Ask every timeThe safe default. You approve each action. Slow, but you learn exactly what Claude is doing.
Allow-list (recommended)Pre-approve reads, tests, git, and the dev server in settings.json. Gate installs, deletes, and network calls.
Skip permissionsThe "nuclear" flag. Even Boris Cherny, Claude Code's creator, says he never uses it.

💡 Quick tip: CLAUDE.md vs. memory

CLAUDE.md is the manual you hand a new hire on day one — rules you wrote yourself. Auto-memory is more like a colleague who's worked with you for months and has just picked up your habits without being told. Both make Claude more "you," but one is written, the other is learned.

Part Three

Power features

This is where Claude Code stops being merely useful and starts being genuinely different from any chatbot you've used.

15

Extended thinking

Simple tasks don't need much thought; hard ones do. Extended thinking gives Claude a dedicated reasoning budget to work through a problem step-by-step before it acts — on by default now, no magic words required.

ExampleAsk it to design a database schema for a multi-tenant app, and it visibly reasons through trade-offs before writing anything.
16

Slash commands

Type a forward slash plus a name to trigger a specific, repeatable action — a shortcut for something you'd otherwise have to explain every time.

Example/init sets up a new project, /clear wipes the conversation, /help lists every shortcut you have.
17

Skills

Claude Code is a generalist — decent at almost everything. Skills are pre-written expert instructions that make it excellent at one specific task, like copywriting or frontend design. Claude reads the skill (and its supporting files) before it builds.

ExampleInstall a copywriting skill, and every marketing request follows that exact playbook.
18

Hooks

Custom scripts that fire automatically at a specific moment — no AI tokens spent, no permission asked, every single time.

ExampleA hook that auto-formats every file Claude saves, or logs every command it runs.
19

MCP servers

By default Claude Code only sees files on your machine. MCP (Model Context Protocol) servers connect it to external tools — Airtable, Notion, Asana — so it can pull data and push updates across your whole stack from one conversation.

ExampleConnect an Asana MCP server, then say "create a task for the bug we just found" — it appears directly in Asana.
20

Sub agents

A specialist that runs in its own separate context window with its own instructions, does a task independently, and reports the result back to your main conversation — keeping your main context clean.

Example"Go analyze this report and come back with your findings" — a self-contained job a sub agent can finish unsupervised.
21

Agent teams

Sub agents can only report to the main agent — a bottleneck once you have several. Agent teams let teammates talk directly to each other and share one task list instead.

ExampleBuilding a SaaS app: an API developer, a front-end developer, and a tester all working in parallel, coordinating with each other.
22

Multimodal support

Sometimes showing beats telling. Claude Code can read images — paste a screenshot of a bug and it sees exactly what's wrong. It also works in reverse: paste a design you like, and Claude builds toward it.

ExampleScreenshot a broken layout, paste it in, say "fix this" — instead of typing a paragraph describing the bug.

Sub agents vs. agent teams

🎯 Sub agents — hub and spoke

Each specialist reports only to the main agent. Great for one self-contained task at a time, but with five or more specialists, the main agent becomes a bottleneck.

🕸️ Agent teams — mesh

Teammates run in their own instances, talk directly to each other, and share a task list. Better for genuinely complex, collaborative builds.

💡 Quick tip: skill, hook, or sub agent?

Use a skill when you want Claude to be better at something in the current conversation. Use a hook when a rule should fire automatically without spending any AI tokens. Use a sub agent when the task is entirely self-contained and can be done unsupervised.

Part Four

Using it for real

The last five concepts are the practical, real-world stuff — how you undo mistakes, pay for it sensibly, and run more than one Claude at once.

23

Checkpoints

Claude Code moves fast and occasionally goes down the wrong path. It automatically snapshots your code before every file edit, with zero setup from you.

ExampleType /rewind to see every prompt from your session and pick a point to restore — just the code, just the conversation, or both.
24

Git integration

Git (and GitHub) is version control — it tracks every change, when, and why. Connecting your account is what powers checkpoints, and how you review, roll back, or work with a team without overwriting each other.

ExampleYou never type a git command yourself — Claude commits and tracks changes quietly in the background.
25

Headless (CLI) mode

Normally you go back and forth, approving steps. Headless mode removes the human entirely — add a flag, and Claude runs a full loop by itself, no approvals, no waiting.

Exampleclaude -p "fix all failing tests" runs start to finish with zero input from you.
26

Pricing

Two ways to pay: a flat monthly plan with generous, predictable usage, or the API, charged per token — cheaper for light, occasional use but harder to predict at scale.

ExampleBuilding daily? A flat plan usually wins. Opening Claude Code once a week? The API may cost less overall.
27

Work trees

Separate working directories, each with its own files and branch, sharing one repository history — so multiple Claudes can work on unrelated tasks at once without stepping on each other.

ExampleRun claude --worktree feature-auth in one terminal and claude --worktree bugfix-login in another. Merge each branch back when it's done.

🌀 Going further

Headless mode has a bigger sibling called the Ralph loop — an official plugin, named after Ralph Wiggum from The Simpsons. Instead of running once and stopping, it keeps re-feeding the same prompt as files get built, and Claude works out what's left to do each time. People have used it to ship entire projects overnight. Think of it as headless mode with a persistent memory of "are we done yet?"
