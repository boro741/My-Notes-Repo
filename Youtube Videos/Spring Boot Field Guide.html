The big picture

Before any code, zoom out. At the end of this guide you will have a small web service that other programs can call. A request comes in from a client, passes through a few layers inside your app, reaches a database, and the answer travels back the same way.

Your Spring Boot app, built by Maven
ClientA browser or Postman sends a request
ControllerReceives the request and returns JSONSection 10
ServiceHolds the business logicSection 4
RepositorySaves and loads dataSection 8
DatabasePostgreSQL stores everythingSection 7
Packaged in a Docker container and hosted on AWS Section 11

Spring Boot wires those layers together for you. It creates the objects (Section 5), applies sensible default settings (Section 6) and converts data to JSON (Section 9). Maven builds and runs the project (Section 3).

We will learn every one of these pieces, one at a time. We start with a single Hello World endpoint, then add Maven, the Spring basics, a database and the full API, and finish by putting it on the internet. Each step adds one box to the picture above.

1. Set up your project

You need Java 17 or later and an IDE. The course uses IntelliJ IDEA Community, which is free. Then open start.spring.io, a website that generates an empty Spring Boot project for you to download.

2. Your first endpoint

Create one class in src/main/java. Run the application from your IDE, then open http://localhost:8080/hello in a browser. You will see the text.

@RestController
public class HelloWorldController {

    @GetMapping(path = "/hello")
    public String helloWorld() {
        return "Hello World";
    }
}

The generated project also contains a main class, a config file, a test and a build file:

  • QuickStartApplication is the entry point. Its main method starts Spring.
  • application.properties holds your settings. It starts empty.
  • QuickStartApplicationTests contains one test that checks the app starts.
  • pom.xml lists your dependencies and build settings for Maven.
Key terms
Annotation
A label that starts with @. It tells Spring how to treat the class or method underneath.
REST API
A way for programs to talk over the web using URLs and HTTP methods such as GET and POST.
Endpoint
One URL your API responds to, such as /hello.
Controller
A class that receives web requests and returns responses.
Port 8080 / Tomcat
Tomcat is the web server bundled inside your app. It listens on port 8080 by default.

3. Maven in five minutes

Maven downloads your dependencies, including the dependencies of those dependencies. It also compiles, tests and packages your code. Spring Boot projects include mvnw, a small script that runs Maven for you, so you do not need to install it.

Maven runs goals in a fixed order. The ones you will use most come from the default lifecycle. Running a later goal runs all the earlier ones first.

CommandWhat it does
./mvnw cleanDeletes the target folder with all build output.
./mvnw compileTurns your Java code into bytecode, which the JVM can run.
./mvnw testCompiles, then runs your unit tests.
./mvnw packageCompiles, tests, then builds the JAR in target.
./mvnw verifyDoes all of the above, then runs integration tests and checks.

Where files live

Maven expects a fixed folder layout. Spring Boot relies on it.

FolderContents
src/main/javaYour application code.
src/main/resourcesConfig files such as application.properties.
src/test/javaTests, in the same packages as the code they test.
src/test/resourcesConfig used only in tests. It overrides the main config.
targetBuild output, including your JAR.

Three ways to run the app locally: press play in the IDE, run the JAR with java -jar target/quickstart-0.0.1-SNAPSHOT.jar, or run ./mvnw spring-boot:run. Stop it with Ctrl+C.

Habit worth copying. Run ./mvnw clean verify before you push code. It proves the whole project still builds and passes its tests.
Key terms
Build tool
Software that compiles, tests and packages your project in repeatable steps.
Transitive dependency
A library needed by a library you asked for. Maven fetches these automatically.
Lifecycle, phase, goal
A goal is one task. A phase groups goals. A lifecycle is the ordered list of phases.

4. Spring, Spring Boot and layers

Spring Framework does the heavy lifting: database access, web APIs and more. It is very configurable, which means you configure a lot on every new project. Spring Boot sits on top and fills in sensible defaults. You keep Spring's flexibility and skip the repetitive setup.

Most Spring apps are split into three layers. Each one has one job, and calls only go downward.

PresentationControllers. Turn requests into calls and send results back to the user.
ServiceBusiness logic. Uses the persistence layer to meet the app's requirements.
PersistenceTalks to the database through repositories or DAOs.

The payoff is flexibility. Swap a REST API for GraphQL and only the presentation layer changes. Swap the database and only the persistence layer changes.

5. Beans and dependency injection

Say a class needs three helper classes. If it creates them with new, swapping one means editing that class. With dependency injection, the class only declares what it needs, usually as constructor parameters. Spring creates the objects and hands them over.

In the course, a ColorPrinter needs red, blue and green printers. Replacing the English printers with Spanish ones takes one change, and ColorPrinter stays untouched.

Two ways to declare a bean

// 1. In a configuration class
@Configuration
public class PrinterConfig {
    @Bean
    public RedPrinter redPrinter() { return new EnglishRedPrinter(); }
}

// 2. Directly on the class
@Component        // @Service does the same thing, with a clearer name
public class SpanishGreenPrinter implements GreenPrinter { ... }

When the app starts, Spring runs a component scan. It walks through your packages, collects every bean into the application context, and injects them wherever they are asked for. If a needed bean is missing, startup fails with a clear message.

The scan begins at the package of your main class and covers everything below it. A class placed outside that package is never found.

What @SpringBootApplication really is

It bundles three annotations: @Configuration (this class can declare beans), @ComponentScan (find beans from here down) and @EnableAutoConfiguration (set up defaults, covered next).

Key terms
Interface
A list of methods a class promises to provide. Code that depends on an interface does not care which class sits behind it.
Bean
An object created and managed by Spring.
Dependency injection
Spring supplies the objects a class needs instead of the class creating them. Also called autowiring.
Inversion of control
The general idea behind it: something outside your class takes over control of creating dependencies.
Application context
Spring's pool of beans, ready to be handed out.

6. Starters, auto-configuration and settings

A starter is a bundle of dependencies for one job. spring-boot-starter-web brings Spring MVC, JSON support and Tomcat. Auto-configuration then looks at what is on your classpath and creates the matching beans. A rule like @ConditionalOnClass means "only set this up if that library is present". You never need to read these classes to use Spring Boot, but knowing they exist makes it feel less like magic.

Changing a default

Put a key and value in src/main/resources/application.properties. Every key is listed in Spring's "common application properties" page.

# application.properties
server.port=8181
# application.yaml, same setting in YAML format
server:
  port: 8181

Settings can also come from environment variables, which is how you configure apps in Docker. Take the key, make it uppercase, and replace dots and hyphens with underscores: server.port becomes SERVER_PORT.

SERVER_PORT=8383 ./mvnw spring-boot:run

Your own settings

Custom values can be loaded the same way with @ConfigurationProperties. The prefix is the start of the key.

@Configuration
@ConfigurationProperties(prefix = "pizza")
public class PizzaConfig {
    private String sauce;
    private String topping;
    private String crust;
    // getters and setters (the course uses Lombok's @Data)
}

Now pizza.sauce=barbecue in the properties file, or PIZZA_SAUCE=tomato in the environment, fills the field.

Test settings. Files in src/test/resources override the main ones during tests. Use this to point tests at an in-memory database.
Key terms
Classpath
The set of libraries and files available to your running app.
Environment variable
A named setting provided by the operating system or the container, outside your code.
Lombok
A library that generates getters, setters and constructors from annotations such as @Data.

7. Talking to a database

Database tools stack up in layers. Each layer builds on the one below it.

Database driverLets Java talk to a specific database such as PostgreSQL or MySQL.
JDBCJava's low-level API. You write SQL and map the results to objects yourself.
Spring JDBCAdds JdbcTemplate, which removes much of the boilerplate.
JPA / HibernateHigh level. You work with Java objects and it generates the SQL.
Spring Data JPAAdds ready-made repositories on top of JPA.

Connecting

For quick experiments, add the H2 in-memory database. Spring Boot finds it and connects with no settings. For a real database, run PostgreSQL with Docker Compose (docker-compose up) and give Spring the connection details:

spring.datasource.url=jdbc:postgresql://localhost:5432/postgres
spring.datasource.username=postgres
spring.datasource.password=change-me
spring.datasource.driver-class-name=org.postgresql.Driver

Two files in src/main/resources can set up the database at startup: schema.sql creates tables and data.sql fills them. Turn them on with spring.sql.init.mode=always. Do not leave that on in production.

The hard way first: a DAO

The course first builds create, read, update and delete classes by hand with JdbcTemplate. This makes clear how much work JPA later removes.

jdbcTemplate.update(
    "INSERT INTO authors (id, name, age) VALUES (?, ?, ?)",
    author.getId(), author.getName(), author.getAge());

The ? placeholders matter. Passing values separately, instead of gluing them into the SQL string, protects you from SQL injection.

Key terms
JDBC
Java Database Connectivity. The standard way to send SQL from Java.
JPA and Hibernate
JPA is a specification for working with databases through objects. Hibernate is the implementation Spring uses.
ORM
Object-relational mapper. A tool that converts between database rows and Java objects. Hibernate is one.
DAO
Data Access Object. A class that holds all database code for one kind of data, so the service layer never sees SQL.
CRUD
Create, Read, Update, Delete. The four basic data operations.
SQL injection
An attack where user input is treated as SQL code.
In-memory database
A database that lives in RAM and disappears when the app stops. Great for tests.

8. Spring Data JPA: the easy way

Swap spring-boot-starter-jdbc for spring-boot-starter-data-jpa. Delete the DAOs and schema.sql. Then turn your plain classes into entities, which are Java classes mapped to database tables.

@Entity
@Table(name = "authors")
public class AuthorEntity {
    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "author_id_seq")
    private Long id;
    private String name;
    private Integer age;
}

A book points to its author with a many-to-one relationship, so one author can have many books:

@Entity
@Table(name = "books")
public class BookEntity {
    @Id
    private String isbn;
    private String title;

    @ManyToOne(cascade = CascadeType.ALL)
    @JoinColumn(name = "author_id")
    private AuthorEntity author;
}

CascadeType.ALL means saving a book also saves its author.

Instead of schema.sql, let Hibernate build the tables from your entities:

spring.jpa.hibernate.ddl-auto=update

Repositories need no code

@Repository
public interface AuthorRepository extends CrudRepository<AuthorEntity, Long> {
    Iterable<AuthorEntity> findByAgeLessThan(int age);

    @Query("SELECT a FROM AuthorEntity a WHERE a.age > ?1")
    Iterable<AuthorEntity> findAuthorsWithAgeGreaterThan(int age);
}

Extending CrudRepository gives you save, findById, findAll, deleteById and more, with no implementation. save handles both create and update. Spring Data can also build a query from a method name like findByAgeLessThan. When the name is not enough, write the query yourself with @Query.

Careful in production. ddl-auto=update is handy while learning. Real projects usually manage schema changes with a migration tool.
Key terms
Entity
A Java class that represents a table row.
Repository
An interface that gives you ready-made database operations for one entity.
Sequence
A database counter that hands out 1, 2, 3… for new IDs.
HQL / JPQL
A query language like SQL, but written against your Java classes and fields instead of tables and columns.

9. JSON and Jackson

APIs exchange data as JSON, a text format of keys and values. Spring Web uses Jackson to convert between JSON and Java objects automatically. Turning an object into JSON is marshalling. Turning JSON into an object is unmarshalling.

ObjectMapper mapper = new ObjectMapper();
String json = mapper.writeValueAsString(book);        // object to JSON
Book copy  = mapper.readValue(json, Book.class);       // JSON to object

Two annotations come up constantly. @JsonProperty("year") renames a field in the JSON. @JsonIgnoreProperties(ignoreUnknown = true) stops Jackson from failing when the JSON has fields your class does not know. Classes used with Jackson also need a no-argument constructor.

10. Building the REST API

The API has two resources, books and authors. URLs use plural nouns. Books use the ISBN as their ID, which you supply, so create is a PUT. Authors get a generated ID, so create is a POST.

ActionBooksAuthorsSuccess
CreatePUT /books/{isbn}POST /authors201 Created
Read oneGET /books/{isbn}GET /authors/{id}200, or 404 if missing
Read manyGET /booksGET /authors200, even if empty
Full updatePUT /books/{isbn}PUT /authors/{id}200
Partial updatePATCH /books/{isbn}PATCH /authors/{id}200
DeleteDELETE /books/{isbn}DELETE /authors/{id}204 No Content

A full update replaces the whole object. A partial update changes only the fields you send.

How a request flows

The controller never touches entities. It receives a DTO, converts it to an entity with a mapper, and passes it to the service. The service calls the repository. The result travels back the same way. ModelMapper is a library that does the DTO-to-entity copying for you.

@PostMapping("/authors")
public ResponseEntity<AuthorDto> createAuthor(@RequestBody AuthorDto dto) {
    AuthorEntity saved = authorService.save(authorMapper.mapFrom(dto));
    return new ResponseEntity<>(authorMapper.mapTo(saved), HttpStatus.CREATED);
}

Nested objects and big lists

To save a book and its author in one request, set ModelMapper's matching strategy to loose so nested objects convert too. For long lists, use pagination: extend PagingAndSortingRepository, accept a Pageable in the controller, and return a Page. Callers then control the result with ?page=0&size=20.

Testing it

The course writes unit tests with Mockito, then integration tests with @SpringBootTest against an H2 database in PostgreSQL mode. Controller tests use MockMvc, which sends fake requests and checks status codes and JSON fields. Add @DirtiesContext so each test starts with a clean database. Without it, data from one test leaks into the next.

Key terms
HTTP method
The verb of a request. GET reads, POST and PUT create or replace, PATCH changes part, DELETE removes.
Status code
A number in the response that says what happened. 200 OK, 201 Created, 204 No Content, 404 Not Found.
DTO
Data Transfer Object. A plain class for data crossing the API boundary, so the outside world never depends on your database classes.
Unit vs integration test
A unit test checks one class in isolation. An integration test starts the real app and checks parts working together.
Pagination
Returning a large list in small pages instead of all at once.

11. Deploy to AWS

The last step packages the app in a Docker container, a sealed box holding your app and everything it needs to run, and hosts it on AWS Lightsail.

Dockerfile
FROM openjdk:17
COPY target/*.jar app.jar
ENTRYPOINT ["java", "-jar", "app.jar"]
  1. Build the JAR with ./mvnw clean package.
  2. Build the image with docker build -t books .
  3. In Lightsail, create a container service and push the image with the AWS CLI.
  4. Create a PostgreSQL database in Lightsail and note its endpoint, username and password.
  5. Create a deployment: open port 8080 and set SPRING_DATASOURCE_URL, SPRING_DATASOURCE_USERNAME and SPRING_DATASOURCE_PASSWORD as environment variables.
  6. Set the health check path to /books, because it always answers 200.
If the deployment fails. The first attempt failed its health check because the smallest instance started too slowly. A larger instance and longer timeouts fixed it. In a real project, keep passwords in a secrets store instead of plain environment variables.

Once it is live, call the public HTTPS address with the same requests you used locally. That is the full journey: a project from Spring Initializr, running in the cloud.

Key terms
Docker image
The packaged, read-only blueprint. Running it creates a container.
Health check
A request the host sends repeatedly to confirm your app is alive.
