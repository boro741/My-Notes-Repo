1 S3 Overview

Amazon S3 (Simple Storage Service) is one of the most essential services in AWS. It provides infinitely scaling file storage in the cloud, powering major websites, applications, and AWS service integrations globally.

Real-world Analogy Think of an S3 Bucket as an unlimited digital locker in the cloud where you can store any file safely and access it from anywhere.

Common Use Cases

  • Backup and file storage (documents, photos, disk images).
  • Disaster recovery (copying files to another region so you stay safe if one region fails).
  • Archival (cheap storage for old records and audits).
  • Hosting application files, media assets (videos/photos), and static websites.
  • Data lakes for big data analytics.
  • Distributing software updates.
Real Examples NASDAQ stores 7 years of financial records in S3 Glacier (archival tier). Sysco runs big data analytics directly on data saved in S3 buckets.

Buckets

  • Buckets act like top-level storage containers or folders in the cloud for your files (objects).
  • Buckets are created in a specific AWS Region (e.g. Mumbai ap-south-1). The AWS Console shows all buckets together, but each bucket physically belongs to one region.

Bucket Naming Rules

Bucket names must be globally unique across all AWS accounts worldwide (or you can use AWS's new Account Regional Namespace feature to reuse names within your account).

Naming Rules Use only lowercase letters and numbers. No uppercase letters, no underscores, and cannot look like an IP address. Keep bucket names simple (e.g., my-company-photos-2024).

Objects (Files)

  • Objects are the actual files stored in S3. Every object has a Key, which is its full file path name.
  • A Key consists of a Prefix (folder path) + Object Name (file name). For example, in images/2024/photo.jpg, images/2024 is the prefix and photo.jpg is the object name.
  • S3 does not have true physical sub-directories. It is a flat key-value store, but the AWS console shows slashes (/) as folders for easy viewing.
  • Max Object Size: 50 TB per single object.
  • Files larger than 5 GB must be uploaded using Multi-part Upload (splitting the file into smaller chunks).
  • Objects can contain Metadata (details about the file), Tags (up to 10 key-value pairs for security rules), and a Version ID.

2 S3 Hands On

Quick guide to creating an S3 bucket and uploading files via the AWS Console:

Creating a Bucket

  • Select an AWS Region (e.g. Ireland eu-west-1).
  • Bucket Type: General Purpose (standard default choice).
  • Object Ownership: ACLs disabled (recommended default security option).
  • Block Public Access: Keep enabled by default to keep data safe.
  • Bucket Encryption: Enabled by default using Amazon S3 managed keys (SSE-S3).

Uploading & Viewing Objects

After uploading a file (like coffee.jpg), click the object to see its details and its Object URL.

Important Security Note Clicking the console's "Open" button works because AWS creates a temporary signed link for you. But copying the raw Object URL directly into a browser gives an AccessDenied error because S3 buckets are private by default.

The console's "Open" button uses a pre-signed URL (a temporary access pass containing security credentials), which lets authorized users view private objects easily.

3 S3 Security: Bucket Policy

Ways to Secure S3 Buckets

Security OptionDescription
IAM Policies (User-based)Attached to an IAM user or role to define what S3 actions they can take
Bucket Policies (Resource-based)JSON policy attached directly to the bucket; can make a bucket public or grant cross-account access
Object / Bucket ACLsLegacy access control rules (usually kept disabled)
EncryptionEncrypts data stored on disk (at rest) or in transfer
Exam Rule An IAM user can access an S3 object if: IAM permissions allow it OR the bucket policy allows it — AND there is no explicit Deny statement anywhere.

Bucket Policy Structure (JSON)

  • Resource — Bucket or object ARN (e.g. arn:aws:s3:::my-bucket/* for all objects inside).
  • Effect — Allow or Deny.
  • Action — S3 API actions being permitted or blocked (e.g. s3:GetObject).
  • Principal — Target user or account (* means public access to everyone).

Four access methods to S3: Public web visitors, local IAM users, EC2 instances using IAM roles, or users from another AWS account.

Block Public Access Guardrail "Block Public Access" is a master safety switch. Even if a bucket policy allows public access, this safety switch overrides it and keeps the bucket private unless you deliberately turn it off.

4 Bucket Policy Hands On

Steps to make a file (like coffee.jpg) publicly readable:

  1. Go to the bucket's Permissions tab and turn off Block Public Access (confirm the warning box).
  2. Use the AWS Policy Generator to build a policy: Effect = Allow, Principal = *, Action = s3:GetObject, Resource = arn:aws:s3:::your-bucket-name/*.
  3. Paste the JSON policy into the Bucket Policy editor and save.
  4. Now the raw Object URL loads directly in any browser.

5 S3 Static Website Hosting

Amazon S3 can directly host static websites (HTML, CSS, JS, images) without needing any EC2 web server.

Important If opening the website URL gives a 403 Forbidden error, it means your bucket policy is missing public read permissions for GetObject.

Steps to Enable Static Hosting

  1. Upload website files (such as index.html, error.html, images).
  2. Under bucket Properties → Static website hosting, select Enable and type index.html as your main page.
  3. Save to generate your unique S3 Bucket Website Endpoint URL.

6 S3 Versioning

Versioning keeps multiple historical copies of an object in the same bucket whenever files are re-uploaded or modified.

Best Practice Always enable versioning. It guards against accidental file deletion and lets you recover earlier file versions easily.

Delete Marker vs Permanent Deletion

Real-world Analogy Deleting a file normally when versioning is enabled puts a Delete Marker over the file (like placing a sticky note saying "Hidden" on top of a document). If you remove that sticky note (delete the delete marker), your original file appears back immediately! However, deleting a specific Version ID acts like putting the document in a paper shredder — it is deleted permanently.
  • Normal Delete = Adds a Delete Marker (file appears deleted, but can be restored).
  • Deleting a specific Version ID = Permanent removal (cannot be recovered).

7 S3 Replication

S3 automatically copies objects asynchronously between buckets. Versioning must be enabled on both source and target buckets.

Replication TypeDescriptionCommon Use Cases
CRR — Cross-Region ReplicationReplicates data to a bucket in a different AWS RegionDisaster recovery, lower latency access for global users
SRR — Same-Region ReplicationReplicates data to a bucket in the same AWS RegionLog aggregation, syncing live production data to a testing account
Important Replication Rules
  • Only newly uploaded objects replicate automatically. Existing files require S3 Batch Replication.
  • Permanent deletes of specific Version IDs are never replicated (prevents accidental destruction in the replica bucket).
  • No chain replication (Bucket 1 → Bucket 2 → Bucket 3 does not automatically pass Bucket 1 files to Bucket 3).

8 S3 Storage Classes

S3 offers different storage tiers to balance cost and retrieval speed based on how frequently you access files.

Durability vs Availability

  • Durability (Data Loss Protection): All S3 storage classes provide 11 Nines (99.999999999%) durability. You are practically never going to lose your data.
  • Availability (Uptime Access): Varies per class (e.g. S3 Standard guarantees 99.99% annual availability).

S3 Storage Tiers Overview

Storage ClassAvailabilityBest Used For
S3 Standard99.99%Frequently accessed data, fast retrieval, active applications
S3 Standard-IA (Infrequent Access)99.9%Data accessed less often (e.g., monthly backups), rapid retrieval when needed
S3 One Zone-IA99.5%Stored in 1 AZ only (cheaper; suitable for secondary recreatable backups)
S3 Glacier Instant Retrieval99.9%Archived data accessed once a quarter with millisecond retrieval
S3 Glacier Flexible Retrieval99.9%Archive data with retrieval options: Expedited (1-5 min), Standard (3-5 hrs), Bulk (5-12 hrs)
S3 Glacier Deep Archive99.9%Lowest cost long-term storage (retrieval takes 12 to 48 hours)
S3 Intelligent-Tiering99.9%Automated tiering that moves files between frequent & infrequent tiers without retrieval fees
Real-world Analogy Think of Glacier retrieval options like package shipping: Instant Retrieval is express same-day delivery, Flexible Retrieval is standard post (a few hours), and Deep Archive is economic cargo shipping (takes 1-2 days, lowest cost).

✓ Cheat Sheet

Key Facts to Remember

  • S3 buckets are created in a specific AWS Region; names must be globally unique.
  • Objects are files stored with a unique Key (prefix + filename). Maximum single file size is 50 TB. Use multi-part upload for files > 5 GB.
  • Objects are private by default. Access requires IAM policy OR Bucket policy approval with no explicit deny.
  • Static website hosting requires public read permissions on the bucket.
  • Versioning: Normal delete adds a Delete Marker (restorable); deleting a version ID is permanent.
  • Replication requires versioning on both source and target buckets. Only new objects replicate automatically.
  • All storage classes share the exact same 11 Nines durability.

Simple Mental Model

S3 is an unlimited digital locker in the cloud. You put files (objects) into buckets, manage permissions with IAM or bucket policies, protect files using versioning and replication, and save money by auto-archiving older files into cheaper Glacier storage classes while keeping rock-solid 11-nines durability.
