1 What is a DNS?

DNS stands for Domain Name System. It acts as the phonebook of the internet. Its primary role is translating human-friendly web links (like www.google.com) into computer-readable IP addresses (like 142.250.190.46) that servers use to communicate.

Domain names are structured hierarchically, read from right to left:

  • Root: The trailing dot at the end of every web domain (usually hidden).
  • TLD (Top-Level Domain): The domain extension such as .com, .org, or .gov.
  • Second-Level Domain: The unique brand name registered (e.g. example.com).
  • Subdomain: A prefix before the domain name (e.g. www.example.com or api.example.com).
  • FQDN (Fully Qualified Domain Name): The complete web path (e.g. api.www.example.com.).

Key Terminology

  • Domain Registrar: An accredited company where you purchase and register domain names (e.g. Amazon Route 53, GoDaddy).
  • DNS Records: Mapping entries configured inside a domain (e.g. A, AAAA, CNAME, NS records).
  • Zone File: A text file containing all DNS records configured for a domain.
  • Name Servers: Special DNS servers that store zone files and answer domain queries.

How a Recursive DNS Lookup Works

When you enter a web address, your request travels through a lookup chain until the exact IP address is located:

Each server points to the next level down. Your local DNS resolver completes the search recursively, then caches the final answer.
Real-World Analogy Finding a server IP via DNS is like asking for directions in a new city. You ask a traffic officer (Root server) who says "that area is in the North district" (.com TLD). You travel there and ask a local guide (.com TLD server) who says "that building is managed by AWS Route 53". Route 53 then hands you the exact house number (IP address).
Best Practice Understanding recursive DNS resolution clarifies why DNS caching, TTL expiry, and propagation delays occur when modifying web server IPs.

2 Route 53 Overview & Hosted Zones

Amazon Route 53 is a highly available, scalable, managed, and authoritative DNS service from AWS. "Authoritative" means you maintain full control over configuring domain records.

  • Acts as a Domain Registrar — register and buy custom web domains directly.
  • Performs automated Health Checks on your cloud applications.
  • The only AWS service offering a 100% Availability SLA guarantee.
Origin of the Name: "53" refers to network Port 53 — the standardized networking port reserved for DNS services.

Anatomy of a DNS Record

Every DNS record created in Route 53 contains:

  • Domain Name: The hostname (e.g. example.com or app.example.com).
  • Record Type: Defines record behavior (e.g. A, AAAA, CNAME).
  • Value: The target IP address or hostname destination (e.g. 12.34.56.78).
  • Routing Policy: How Route 53 responds to client DNS queries.
  • TTL (Time To Live): Caching duration allowed for DNS resolvers.

Public vs Private Hosted Zones

A Hosted Zone is a container storing DNS records that define traffic routing for a domain.

Public hosted zones answer internet queries; Private hosted zones answer queries only from designated Amazon VPCs.
Cost Reminder Every Route 53 Hosted Zone costs $0.50 per month, and domain registrations start at approximately $12 per year.

3 Registering a Domain (Hands-On)

Steps to purchase and register a domain name directly in Route 53:

  1. Navigate to Register Domains in Route 53 console and search for domain availability.
  2. Select subscription term (e.g. 1 year) and enable/disable auto-renew.
  3. Enter registrant, admin, and technical contact details.
  4. Enable Privacy Protection to conceal your personal contact details from public WHOIS databases.
  5. Review order details and submit payment.

Once registered, Route 53 automatically creates a Public Hosted Zone populated with default NS (Name Server) and SOA (Start of Authority) records.

Renewal Caution: Disabling auto-renew without manual renewal will cause domain expiration, allowing outside parties to register your expired domain.

4 First Records & Demo Infrastructure

To configure a basic record: Enter Record Name (e.g. test.example.com), select Type (e.g. A), enter Value (server IP address), set TTL, and choose Routing Policy (e.g. Simple).

CLI tools used to query and verify DNS records from a terminal:

  • nslookup <domain> — Standard command line utility on Windows.
  • dig <domain> — Detailed query utility on Mac/Linux (displays TTL count down).

sudo yum install -y bind-utils

5 TTL (Time To Live)

TTL (Time To Live) instructs web browsers and DNS resolvers how long to cache a DNS answer before querying Route 53 again.

While an answer remains cached locally, server IP updates made in Route 53 will not reach clients until the TTL window expires.
SettingHigh TTL (e.g. 24 Hours)Low TTL (e.g. 60 Seconds)
Query Traffic / CostsLower — Resolvers cache answers longer, making fewer calls to Route 53.Higher — Resolvers query Route 53 frequently.
Change Propagation SpeedSlower — Clients retain old cached IP addresses for up to 24 hours.Faster — Clients fetch updated IP addresses rapidly.
Best Practice Before performing server migrations, temporarily lower your record TTL (e.g. to 60s). Wait out the previous long TTL duration, perform the server IP migration, and verify rapid client propagation.
Rule: TTL configuration is mandatory for all DNS records except Alias records (managed automatically by Route 53).

6 CNAME vs Alias

Both record types map a domain name to another domain name, but they possess fundamental differences heavily tested on AWS exams.

FeatureCNAME RecordAlias Record
Target DestinationAny external domain hostnameSpecific AWS resources only (ALB, CloudFront, S3 Website, etc.)
Apex / Root Domain Support? (e.g. example.com)❌ No (Forbidden at zone apex)✅ Yes (Supported at zone apex)

Health Check SupportNo native health checksNative built-in health check awareness
Record TypeCNAMEConfigured as A or AAAA type with Alias enabled
Alias records solve the limitation of CNAME records by allowing root apex domains (e.g. example.com) to map directly to AWS managed resources.

Supported AWS Targets for Alias Records

  • Elastic Load Balancers (ALB, NLB, CLB)
  • Amazon CloudFront Distributions
  • AWS API Gateway Endpoints
  • AWS Elastic Beanstalk environments
  • Amazon S3 Static Website Endpoints (not raw S3 bucket names)
  • Amazon VPC Interface Endpoints
  • AWS Global Accelerator
  • Another Route 53 record in the same hosted zone
Exam Distinction: You cannot create an Alias record pointing directly to a raw EC2 instance hostname. Alias records target AWS-managed service resources only.

7 Routing Policies & Simple Routing

Route 53 offers 7 specialized routing policies: Simple, Weighted, Latency, Failover, Geolocation, Geoproximity, IP-Based, and Multi-Value Answer.

Core Principle Route 53 DNS routing does not handle or proxy web traffic. It simply answers client queries with the chosen server IP. Clients then connect directly to that IP address.

Simple Routing Policy

Directs traffic to a single resource. If multiple IP values are added to one Simple record, Route 53 returns all values to the client, and the client browser selects one at random. Health checks are not supported with Simple routing.

8 Routing Policy: Weighted

Directs user traffic based on assigned relative percentage weights.

Calculation Formula: Traffic % for Record A = Weight A ÷ (Sum of All Record Weights). Weights do not need to add up to 100.

Relative weights distribute DNS query responses: 70% to us-east-1, 20% to eu-central-1, 10% to ap-southeast-1.

Use Cases

  • Load balancing web traffic across regional data centers.
  • Canary Testing: Route 1% of web traffic to a newly deployed software version while sending 99% to the stable release.
  • Setting a record weight to 0 stops traffic to that resource completely.
Key Rule: All records in a weighted record set must share the exact same record name and record type.

9 Routing Policy: Latency-Based

Routes users to the specific AWS Region providing the lowest network latency (fastest response time) for their location.

Route 53 evaluates real-time network latency data across global AWS regions to determine optimal routing.

Real-World Analogy Latency routing selects the server that responds the fastest to the user right now, rather than relying purely on geographical map distance.

10 Health Checks

Health checks monitor backend endpoints continuously, allowing Route 53 to stop routing traffic to unhealthy servers automatically.

~15 global health checkers test target endpoints on a schedule, looking for 2xx/3xx HTTP response codes.

Key Configuration Parameters

  • Check Intervals: Standard (30 seconds) or Fast (10 seconds, additional cost).
  • Supported Protocols: HTTP, HTTPS, TCP.
  • Failure Threshold: Consecutive failed attempts required before marking an endpoint unhealthy (default: 3).
  • Healthy Response Codes: HTTP status codes 2xx and 3xx pass health checks.
Firewall Rule: Route 53 health checkers reside on the public internet. Security groups and firewalls must explicitly allow incoming traffic from public Route 53 Health Checker IP ranges.

Three Health Check Types

Health Check TypeMonitored Target
Endpoint Health CheckMonitors a public IP or hostname directly over HTTP, HTTPS, or TCP.
Calculated Health CheckCombines multiple child health checks using AND/OR/NOT logic (up to 256 children). Useful for maintenance windows.
CloudWatch Alarm Health CheckMonitors a CloudWatch alarm. Primary method to health-check private VPC resources that public checkers cannot reach.

11 Routing Policy: Failover

Configures Active/Passive disaster recovery: one Primary active resource and one Secondary standby resource.

A mandatory health check monitors the Primary record. If it fails, Route 53 automatically fails over to answer queries with the Secondary record.
Exam Rule: Failover sets support exactly one Primary and one Secondary record. The health check on the Primary record is mandatory.

12 Routing Policy: Geolocation

Routes users based on their geographic location (by continent, country, or US state). Distinct from Latency routing, Geolocation routes strictly by user physical location.

  • Always create a Default Record to catch users whose location doesn't match specific rules.
  • Use Cases: Website localization (serving local language content), geographic content licensing, location-based load balancing.

13 Routing Policy: Geoproximity

Routes traffic based on geographic distance between users and resources, allowing you to expand or shrink a region's serving area using a Bias value.

  • Positive Bias (+): Expands a region's geographic reach to capture more user traffic.
  • Negative Bias (-): Shrinks a region's geographic reach to reduce incoming traffic.
  • Requires Route 53 Traffic Flow policy editor.
Adjusting positive bias expands a region's geographic coverage zone, shifting user traffic toward it.

14 Routing Policy: IP-Based

Routes DNS queries based on the client's IP address CIDR block. Allows mapping specific client IP ranges (e.g., specific ISP blocks or corporate office networks) to specific endpoints.

15 Routing Policy: Multi-Value Answer

Returns up to 8 healthy records per query, enabling basic client-side load balancing. Unlike Simple routing, Multi-Value Answer integrates natively with Health Checks — filtering out unhealthy records automatically.

16 3rd Party Domains & Route 53

Domain Registrar (purchasing domains) and DNS Management Service (hosting DNS records) are separate roles. You can purchase a domain from a 3rd party registrar (e.g. GoDaddy) and manage its DNS records in Route 53.

Configuration Steps

  1. Create a Public Hosted Zone in Route 53 for your domain name.
  2. Copy the 4 assigned Route 53 Name Server (NS) addresses.
  3. Log into your 3rd-party domain registrar and replace default name servers with the 4 Route 53 NS addresses.

★ Cheat Sheet

Key Facts to Remember

  • DNS translates human domain names → IP addresses recursively via Root → TLD → Authoritative Name Servers.
  • Route 53 provides authoritative DNS, domain registration, and automated health checks backed by a 100% SLA.
  • Hosted zones cost $0.50/month; domain registration starts at ~$12/year.
  • A = IPv4, AAAA = IPv6, CNAME = Hostname to Hostname (non-apex only), NS = Name Servers.
  • Alias Records: Free, apex-supported, target AWS resources (ALB, CloudFront, S3 website, API Gateway), auto-TTL, health-check aware. Cannot target raw EC2 hostnames directly.
  • TTL = Cache duration. High TTL = Lower Route 53 query costs, slower record propagation. Low TTL = Faster propagation, higher query costs.
  • Health Checks: ~15 global checkers; >18% healthy required to pass. HTTP 2xx/3xx pass checks. Types: Endpoint, Calculated, CloudWatch Alarm (for private VPC resources).

Mental Model Recap

Route 53 DNS never handles actual HTTP application data — it acts purely as the internet's phonebook, answering queries with server IP addresses. Routing policies define how Route 53 selects which IP to return: static choice (Simple), percentage split (Weighted), speed (Latency), disaster recovery (Failover), geographic location (Geolocation/Geoproximity), client IP (IP-Based), or healthy multi-record lists (Multi-Value). Alias records provide Route 53's special free, apex-friendly integration with AWS-managed services.
