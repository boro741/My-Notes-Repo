1AWS Budget & Billing Setup

Before creating any AWS resources, set up billing alerts so you never get a surprise bill. AWS is pay-as-you-go — you're billed for what you use, but mistakes (like forgetting to terminate an instance) happen to everyone.

Accessing the billing console

Click your account name (top right) → Billing and Cost Management.

IAM users can't see billing by default. Even with admin permissions, an IAM user won't see billing info until the root account enables it: log in as root → Account settings → "IAM user and role access to billing information" → Edit → activate.
Root account grants billing visibility once; after that, IAM users can view (but shouldn't necessarily manage) billing.
Security best practice: Use the root account only for billing/account management. Use IAM users for everyday work — this limits the damage if IAM credentials leak.

Billing dashboard basics

Month-to-Date Cost
Total spend so far this month
Forecasted Cost
Estimated total for the month based on current usage
Last Month's Cost
Total spend from the previous month

Cost breakdown & Free Tier monitoring

  • Bills → Charges by Service — see exactly which service is costing money (e.g. EC2 instances $20, EBS volumes $8, NAT Gateway $12)
  • Free Tier page — shows current usage vs. free limits, plus a forecast. If the forecast turns red, you're about to exceed the free tier and get charged — stop/terminate resources immediately

Setting up two layers of budget alerts

Two independent safety nets — one catches accidental charges early, the other tracks your overall monthly spend.
Course tip: If you terminate instances after each lab, you should stay within the free tier (EC2 micro instances are free for 750 hours/month for a new account).

After every hands-on lab, do this:

  1. Check Free Tier page — still within limits?
  2. Check Bills → Charges by Service — anything unexpected?
  3. Confirm budget alerts are configured
  4. Terminate resources you're not using

2What is EC2?

EC2 = Elastic Compute Cloud. It's AWS's core Infrastructure-as-a-Service (IaaS) offering — you rent virtual machines on demand instead of buying physical servers.

Core idea: Pay only for what you use, for as long as you use it. Scale up instantly when traffic grows, scale down when it shrinks.

EC2 isn't one thing — it's a family of services

The EC2 "family": the instance itself, plus EBS (storage), ELB (traffic distribution), ASG (auto-scaling) and AMI (templates) all work together.
EC2 Instances
Virtual machines you rent to run your applications
EBS Volumes
Virtual hard drives attached to instances for persistent storage
Elastic Load Balancer (ELB)
Distributes incoming traffic across multiple instances
Auto Scaling Groups (ASG)
Automatically adds/removes instances based on demand
Why this matters: Nearly every company on AWS uses EC2 in some form. Understanding EC2 well means understanding the core of cloud infrastructure.

3What Can You Customize on an Instance?

When launching an EC2 instance, you control almost everything about it:

SettingWhat it controls

CPU & CoresCompute power — from 1 core to 96+ cores
RAMMemory available to the instance
StorageNetwork storage (EBS) or local hardware storage (Instance Store)
Network CardSpeed/type of network interface
Public IP AddressWhether it's reachable from the internet
Security GroupsFirewall — inbound/outbound traffic rules
Bootstrap Script (User Data)Commands that run automatically at first boot
The power of EC2: Configure a machine exactly how you need it, spin it up in seconds, use it, shut it down when done — no physical hardware to maintain.

4Bootstrapping with EC2 User Data

Bootstrapping = automating setup tasks when a machine first starts. EC2 User Data is a script that runs once, right when the instance first launches, and never again.

User Data runs exactly once at boot — never again on reboot or restart.

What you typically do with it

  • Install software updates/patches
  • Install applications (web servers, databases, etc.)
  • Download config files from the internet
  • Start services automatically
  • Clone Git repositories
  • Set up monitoring agents
Trade-off: The more you put in User Data, the longer the instance takes to boot. Balance automation against startup speed.
Remember: User Data scripts run with root privileges — you never need to prefix commands with sudo.

5EC2 Pricing Models

AWS offers several ways to pay for EC2, each suited to a different kind of workload.

Roughly how much you can save vs. On-Demand — but remember, bigger discounts usually mean less flexibility (Spot can be interrupted anytime).

1. On-Demand

Pay by the second, no commitment. Best for: development/testing, unpredictable workloads, short-term projects, learning AWS.

🏨 Hotel analogy: Walk in anytime, pay full price. No planning needed, maximum flexibility.

2. Reserved Instances

Commit to 1 or 3 years for up to 72% discount. Best for steady-state workloads (databases, always-on web servers).

What you reserve
Instance type, Region, Tenancy, Operating System
Payment options
All Upfront (~72% off), Partial Upfront (~66% off), No Upfront (~65% off)
Convertible Reserved Instances: Slightly less discount (~66%) but let you change instance type/family/OS/tenancy later — good if requirements might shift.
🏨 Book the same room for a year — big discount for long-term commitment.

3. Savings Plans

Commit to spending a fixed $/hour for 1–3 years, get up to 70% discount — but you can mix instance types/sizes/OS as long as you stay within that hourly spend.

🏨 Tell the hotel "I'll spend $300/month" — they discount you, but you can pick different room types as long as you stay in budget.

4. Spot Instances

Bid on unused AWS capacity for up to 90% discount. Best for batch jobs, data analysis, image processing — anything fault-tolerant.

Critical limitation: AWS can terminate your Spot instance anytime the price rises above your bid. Never use Spot for critical apps or databases.
🏨 Last-minute hotel sale on empty rooms — amazing price, but you can get kicked out if someone pays more.

5. Dedicated Hosts

An entire physical server dedicated to you — the most expensive option. Best for compliance requirements or bring-your-own-license software billed per socket/core.

Dedicated Host
You get the physical server itself, full visibility, can reuse server-bound licenses
Dedicated Instance
Runs on hardware dedicated to you, but you don't control which physical server (may share with other instances in your account)
🏨 Rent the entire building for yourself. Maximum privacy, maximum cost.

6. Capacity Reservations

Reserve on-demand capacity in a specific AZ — no discount, but guarantees the capacity is there when you need it. Charged at on-demand rates whether you launch instances or not. Combine with Reserved Instances/Savings Plans to also get a discount.

🏨 Reserve a specific room for a specific night — pay full price even if you don't show up, but the room is guaranteed.

Choosing the right option

WorkloadBest choiceWhy
Dev, testing, learningOn-DemandUnpredictable, start/stop often
Production DB (constant traffic)Reserved InstancesPredictable 24/7 usage, save up to 72%
Flexible web app + DB mixSavings PlansConsistent $/hr spend, flexible instance types
Batch processing, analyticsSpot InstancesTolerates interruption, save up to 90%
Compliance-regulated workloadDedicated HostNeeds physical server isolation
Exam tip: Exam scenarios test whether you can match a workload description to a pricing model. E.g. "database running 24/7 with predictable demand" → Reserved Instance.

6Hands-On: Launch Your First EC2 Instance

Goal: launch an Amazon Linux instance, bootstrap a simple web server via User Data, and understand the launch parameters.

  1. EC2 Console → Instances → Launch Instances
  2. Name it, e.g. "My First Instance" (becomes the Name tag)
  3. Choose an AMI: Amazon Linux 2 (Quick Start) — free-tier eligible, 64-bit x86
  4. Instance type: t2.micro — free-tier eligible (1 vCPU, 1 GB RAM, burstable)
  5. Key pair: create a new one (e.g. my-ec2-key), download the .pem file — needed for SSH
  6. Security group: allow the traffic below
  7. Storage: default 8 GB EBS (gp3), delete-on-termination enabled
  8. User Data (under Advanced Details) — paste the bootstrap script below
  9. Review, confirm t2.micro + HTTP allowed, click Launch Instance
TypeProtocolPortSourcePurpose
SSHTCP22Your IP (or 0.0.0.0/0 for learning only)Terminal access
HTTPTCP800.0.0.0/0Web traffic
HTTPSTCP4430.0.0.0/0Encrypted web traffic (optional)
Security note: 0.0.0.0/0 means "anywhere on the internet." Fine for learning, but in production restrict SSH to your own IP only.

The bootstrap script

#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
echo "<h1>My First AWS Web Server!</h1>" > /var/www/html/index.html
#!/bin/bash
Shebang — run this as a bash script
yum update -y
Update all packages (yum = Amazon Linux's package manager; -y = auto-yes to prompts)
yum install -y httpd
Install Apache web server (httpd = HTTP daemon)
systemctl start httpd
Start Apache immediately
systemctl enable httpd
Make Apache start automatically on every future boot
Why enable matters: Without it, Apache stops for good if the instance reboots. enable is essential for production reliability.

Verify it worked

  • Wait for status Running, copy the Public IPv4 address
  • Paste into your browser (e.g. http://52.123.45.67)
  • You should see "My First AWS Web Server!"

7Instance Lifecycle: Stop vs Terminate

Running ↔ Stopped is reversible. Terminated is final — the instance is gone for good.
StateDescriptionCharged?
RunningActive, can accept traffic✅ Yes — every second
StoppedPowered off but still exists (like a shut-down PC)❌ No compute charge, but EBS storage still costs
TerminatedPermanently deleted❌ No
Stopping / StartingTransitioning between states❌ Usually not charged
STOP = power off, keep the machine and its config — you can start it again later. You lose compute charges but keep storage costs.
TERMINATE = permanently delete. No more charges at all. Use this when you're completely done with an instance.
For this course: Always terminate instances after finishing a lab to avoid ongoing charges. Use "stop" only for a short pause (e.g. overnight).

How to stop/terminate: EC2 → Instances → select instance → Instance State dropdown → choose Stop or Terminate → confirm.

8Connecting via SSH (Optional)

To log in and run commands directly on your instance, you need the .pem key file and the instance's public IP.

# On macOS/Linux terminal:
chmod 400 /path/to/my-ec2-key.pem
ssh -i /path/to/my-ec2-key.pem ec2-user@YOUR_PUBLIC_IP

# Example:
ssh -i ~/Downloads/my-ec2-key.pem ec2-user@52.123.45.67
chmod 400
Restrict file permissions so only you can read the key (required by SSH)
ec2-user
Default username for Amazon Linux (Ubuntu uses ubuntu, Debian uses admin, etc.)
Windows users: Use PuTTY or WSL with the SSH command above — you may need to convert the .pem to .ppk with PuTTYgen.
Never share your .pem file — anyone who has it can log into your instances. Treat it like a password.

📋 Cheat Sheet

Key facts to remember

  • EC2 User Data runs once, at first boot, with root privileges
  • t2.micro = free tier eligible: 1 vCPU, 1 GB RAM
  • Security groups: EC2 instance should only accept traffic on the ports it actually needs (80/443/22)
  • Root volume: deleted by default when instance is terminated (Delete on Termination = enabled)

Mental model recap

  • EC2 = rent a virtual machine, configure it exactly how you want, pay only while running
  • User Data = automation script that runs once, at first launch
  • Stop = pause (reversible) · Terminate = delete forever
  • Always terminate lab instances when done to avoid ongoing charges
