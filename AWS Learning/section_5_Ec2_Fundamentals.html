1AWS Budget & Billing Setup

Before launching any resources in AWS, set up billing alerts. AWS follows a pay-as-you-go model — you only pay for what you use, but forgetting to delete an unwanted server can lead to unexpected charges.

How to Access the Billing Console

Click your Account Name (top-right corner of the AWS Console) → Click Billing and Cost Management.

Important IAM Permission Note: By default, IAM users cannot view billing information even if they have administrator policies. The Root User must enable billing access first: Log in as Root → Account settings → "IAM user and role access to billing information" → Click Edit → Check Activate → Save.
The Root account grants billing permission once; after that, authorized IAM users can view billing details.
Security Best Practice: Use the Root user exclusively for account and billing administration. Perform all daily technical work using IAM users.

Understanding Your Billing Dashboard

Month-to-Date Cost
The total money spent during the current month so far.
Forecasted Cost
The estimated end-of-month bill based on current usage trends.
Last Month's Cost
The final total amount charged in the previous month.

Monitoring Charges & AWS Free Tier

  • Bills → Charges by Service: Shows a clear service-by-service cost breakdown (e.g., EC2 servers, EBS storage drives, NAT Gateways).
  • Free Tier Dashboard: Tracks your usage against monthly free limits (e.g., 750 free hours per month for t2.micro instances). If the bar turns red, you are close to exceeding free tier limits!

Setting Up Budget Alerts

Two budget safety nets — one flags accidental initial charges, while the second tracks total monthly spend.
Pro Tip: Always delete or terminate lab servers after completing practice exercises to stay well within the AWS Free Tier.

After Every Hands-On Lab:

  1. Check the Free Tier page to confirm usage limits.
  2. Open Bills → Charges by Service to verify zero unexpected charges.
  3. Confirm budget email alerts are active.
  4. Terminate (permanently delete) lab servers you are no longer using.

2What is EC2?

EC2 stands for Elastic Compute Cloud. It is AWS's core Infrastructure-as-a-Service (IaaS) offering. Instead of buying physical server hardware, you rent virtual computers (virtual machines) on demand from AWS cloud data centers.

💻 Real-World Analogy: EC2 is like renting a computer in the cloud instead of buying a physical laptop. You can pick the computer's power (RAM, CPU), use it for a few hours, pay only for those hours, and return it when finished!

The EC2 Ecosystem

The EC2 ecosystem: The virtual server (Instance) works together with EBS (hard drive), ELB (traffic balancer), ASG (auto-scaler), and AMI (operating system template).
EC2 Instance
The virtual computer running your software applications.
EBS Volume
The virtual hard drive attached to your instance to store files permanently.
Elastic Load Balancer (ELB)
A smart traffic manager that distributes incoming website visitors across multiple EC2 servers.
Auto Scaling Group (ASG)
Automatically adds more EC2 servers during high web traffic and removes them when traffic drops.

• Security Group: Think of a Security Group like a security guard standing right outside your private house door. It inspects everyone trying to enter your specific room.
• NACL (Network ACL): Think of a NACL like the main gatekeeper at the colony/society entrance gate. It checks traffic entering the entire neighborhood before it reaches individual houses.
• VPC (Virtual Private Cloud): Think of a VPC like a gated housing society / apartment complex in the cloud, isolating your servers safely inside.

4Bootstrapping with EC2 User Data

Bootstrapping means automatically running setup tasks when a computer starts for the first time. In AWS, you do this using an EC2 User Data script. This script executes once when the server is launched, and never runs again on standard restarts.

User Data scripts execute once during initial server startup with full administrator privileges.

Common Uses of User Data Scripts

  • Installing OS updates and patches.
  • Installing web server software (like Apache or Nginx) or database applications.
  • Downloading application code and config files automatically.
  • Starting software services automatically on boot.
Exam Rule: User Data scripts automatically run with root privileges (administrator rights). You do not need to add sudo before commands!

5EC2 Pricing Models

AWS offers 6 different payment plans for EC2 instances based on your workload needs:

Comparing EC2 pricing discounts against On-Demand rates. Larger discounts require longer commitments or accepting interruptions.

1. On-Demand

Pay by the second or hour with no upfront commitment. Ideal for development, testing, learning, and short-term unpredictable applications.

🏨 Hotel Analogy: Walk into a hotel room without booking. You pay standard full rates per night, but enjoy complete freedom to check out anytime.

2. Reserved Instances (RI)

Commit to a 1-year or 3-year term for up to a 72% discount compared to On-Demand rates. Perfect for steady, 24/7 production workloads (like core databases).

🏨 Book the exact same hotel room for 1 full year upfront. The hotel gives you a huge discount for committing long-term.

3. Savings Plans

Commit to spending a specific dollar amount per hour (e.g., $10/hour) for 1 or 3 years. Offers up to 70% discount while giving flexibility to change instance families, OS, or Regions.

4. Spot Instances

Bid on unused AWS computing capacity at up to 90% discount. Best for batch processing, image rendering, data analytics, and fault-tolerant workloads.

Warning: AWS can reclaim Spot instances with a 2-minute warning whenever AWS needs the capacity back. Never use Spot instances for databases or critical web servers!

5. Dedicated Hosts

A physical server fully dedicated to your account. Used for strict compliance requirements or software with core-bound licensing.

6. Capacity Reservations

Reserves EC2 capacity in a specific Availability Zone. Pays standard On-Demand rates, but guarantees that server capacity will be available when needed.

Choosing the Right Pricing Plan

Workload TypeRecommended PlanRationale
Learning, dev/test, temporary jobsOn-DemandNo commitment, short runtime.
Production databases running 24/7Reserved InstancesPredictable usage, maximum long-term savings.
Flexible web servers + microservicesSavings PlansConsistent hourly spend with server flexibility.
Big data processing, video renderingSpot InstancesCan tolerate sudden server termination, maximum cost savings (up to 90%).

6Hands-On: Launch Your First EC2 Instance

Objective: Launch an Amazon Linux server, configure a Security Group, and run a User Data script to start a web server.

  1. Go to EC2 Console → Click Launch Instance.
  2. Enter Name: e.g., My First Web Server.
  3. Select Operating System (AMI): Amazon Linux 2 (Free-tier eligible).
  4. Select Instance Type: t2.micro (1 vCPU, 1 GB RAM — Free-tier eligible).
  5. Key Pair: Create a new Key Pair (e.g., my-key.pem) and download it to log into the terminal safely.
  6. Network Settings / Security Group: Configure rules to allow inbound traffic (see table below).
  7. User Data: Expand Advanced Details and paste the shell script below.
  8. Click Launch Instance.
Traffic TypeProtocolPortSourcePurpose
SSHTCP22Your IP (or 0.0.0.0/0 for practice)Terminal command access.
HTTPTCP800.0.0.0/0 (Anywhere)Public web traffic.
HTTPSTCP4430.0.0.0/0 (Anywhere)Encrypted secure web traffic.

User Data Bootstrap Script

#!/bin/bash
yum update -y
yum install -y httpd
systemctl start httpd
systemctl enable httpd
echo "<h1>My First AWS Web Server!</h1>" > /var/www/html/index.html
yum update -y
Updates software packages automatically.
yum install -y httpd
Installs the Apache HTTP Web Server software.
systemctl start httpd
Starts the web server immediately.
systemctl enable httpd
Ensures Apache starts automatically whenever the server reboots.

7Instance Lifecycle: Stop vs Terminate

Stopping a server is reversible (like shutting down your laptop). Terminating a server is permanent deletion.
Server StateDescriptionBilling Status
RunningServer is online and active.✅ Billed for compute hours.
StoppedServer is powered off. Computer state is preserved on disk.❌ No compute charge (EBS storage drive is still billed).
TerminatedServer and attached root disk are permanently deleted.❌ All billing stops completely.
Lab Rule: Always Terminate practice servers when finished to avoid accidental background charges!

8Connecting via SSH (Optional)

SSH (Secure Shell) allows you to log into your Linux EC2 server terminal securely using your private key file (.pem).

# Set key file permissions (macOS / Linux terminal):
chmod 400 /path/to/my-key.pem

# SSH command syntax:
ssh -i /path/to/my-key.pem ec2-user@YOUR_PUBLIC_IP
chmod 400
Locks permissions so only your user account can read the private key (SSH blocks connection if key permissions are too open).
ec2-user
Default login username for Amazon Linux (Ubuntu uses ubuntu).

📋 Cheat Sheet

Key Concepts to Remember

  • EC2 User Data scripts run once during first boot with root permissions.
  • t2.micro is Free Tier eligible (1 vCPU, 1 GB RAM).
  • Security Groups act as stateful firewalls controlling network port access (e.g., Port 22 for SSH, Port 80 for HTTP).
  • Root EBS volumes are set to Delete on Termination by default.

Mental Model Summary

EC2 lets you rent virtual computers on demand. User Data scripts automate initial software installation. Stop a server to pause compute charges; Terminate a server to delete it permanently and stop all billing.
