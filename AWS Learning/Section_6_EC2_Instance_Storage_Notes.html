1EBS Overview

EBS stands for Elastic Block Store. It is a virtual network hard drive that you attach to an EC2 instance while it runs. EBS allows your data to persist (stay safe) even if the EC2 instance is turned off or terminated.

💾 Real-World Analogy: An EBS volume is like a network USB drive / pendrive. You plug it into your virtual computer over the network. If your virtual computer breaks or shuts down, you can unplug the drive and plug it into a new computer without losing your files!

Core Rules of EBS Volumes

  • One Instance at a Time: By default, an EBS volume can attach to only one EC2 instance at a time (EBS Multi-Attach is a special exception).
  • Locked to One Availability Zone (AZ): An EBS volume created in us-east-1a can only attach to EC2 instances located inside us-east-1a. It cannot directly attach to a server in us-east-1b.
  • Fast Detach & Reattach: Because it connects over the high-speed network, you can detach an EBS volume from one server and reattach it to another server in seconds.
  • Provisioned Capacity: You specify disk size (in GB) and performance (IOPS) upfront, and pay for the storage space you provision.
EBS volumes are locked to a specific Availability Zone (AZ). They cannot directly connect across AZ boundaries.

Delete on Termination Attribute

Controls whether AWS automatically deletes an EBS volume when its attached EC2 instance is terminated:

Volume TypeDefault SettingBehavior when Instance Terminated
Root OS VolumeEnabled (Yes)Automatically deleted along with the instance.
Secondary Attached DrivesDisabled (No)Survives termination and remains saved as an orphaned volume.
Exam Scenario: "How do you preserve data on the root drive when terminating an instance?" → Disable the Delete on Termination attribute for the root volume before terminating.

2EBS Hands-On

  1. View Volumes: Open EC2 Console → Click Storage tab on any instance to view attached root and block drives.
  2. Create Volume: Go to Volumes → Click Create Volume → Select size, type, and choose the exact same AZ as your server.
  3. Attach Volume: Select the created volume → Actions → Attach Volume → Choose your server instance.
AZ Constraint Proof: If your EC2 server is in ap-south-1a and your EBS volume is in ap-south-1b, AWS will not allow you to attach the volume. Always match Availability Zones!

3EBS Snapshots

An EBS Snapshot is a point-in-time point backup of your EBS volume. While an EBS volume is locked to a single AZ, a snapshot is saved across the entire AWS Region.

To move EBS data to another AZ or Region: Take a Snapshot → Restore the Snapshot into a new EBS Volume in the destination AZ.

3 Key Snapshot Features

FeatureFunctionTrade-Off
EBS Snapshot ArchiveMoves snapshots to a low-cost archive tier (up to 75% savings).Retrieving data takes 24 to 72 hours.
Recycle Bin for SnapshotsSaves accidentally deleted snapshots for recovery (1 day to 1 year).Requires setting retention rules.
Fast Snapshot Restore (FSR)Eliminates latency on newly created volumes from snapshots.Higher cost.

4EBS Snapshots Hands-On

  1. Select Volume → Actions → Click Create Snapshot.
  2. To move data across Regions: Right-click Snapshot → Click Copy Snapshot → Select destination Region.
  3. To move data across AZs: Select Snapshot → Actions → Create Volume from Snapshot → Select a different AZ (e.g., us-east-1b).

5AMI Overview

AMI stands for Amazon Machine Image. An AMI is a master template or pre-configured blueprint containing operating system, pre-installed software applications, configuration settings, and permissions.

💿 Real-World Analogy: An AMI is like a master software installation disc or backup clone image. Once you configure a master computer perfectly, you save an AMI clone to stamp out identical servers in seconds!

Types of AMIs

  • AWS Public AMIs: Official clean operating system images provided by AWS (e.g., Amazon Linux 2, Ubuntu).
  • Your Custom AMIs: Golden master images created and maintained by your team.
  • AWS Marketplace AMIs: Pre-built software templates sold by 3rd-party vendors (e.g., SAP, WordPress, Cisco firewalls).
To build a Custom AMI: Launch server → Install software → Stop server → Create Image (AMI).

6AMI Hands-On

  1. Launch an EC2 server and install software packages.
  2. Stop the EC2 server to ensure data integrity.
  3. Right-click Instance → Image and templates → Click Create Image.
  4. Launch new servers directly from your new custom AMI under My AMIs — servers start instantly with pre-installed software!

7EC2 Instance Store

EBS volumes connect over the network. If your application requires extreme read/write speeds, select server types with an EC2 Instance Store — high-speed solid-state drives (SSDs) physically attached to the underlying host server hardware.

EBS offers durable network storage. Instance Store offers ultra-fast physical disk speed, but data is ephemeral (temporary).
Critical Limitation (Ephemeral Storage): EC2 Instance Store is temporary storage. If you stop or terminate the EC2 server, all data stored on the Instance Store is erased permanently. Use it only for temporary caches, buffers, or scratchpad data.

8EBS Volume Types

EBS volumes are divided into 4 main categories:

FamilyVolume TypesBootable?Best Use Case
General Purpose SSDgp2, gp3✅ YesDefault balanced storage for web servers, dev environments.
Provisioned IOPS SSDio1, io2 Block Express✅ YesHigh-performance mission-critical databases requiring low latency.
Throughput Optimized HDDst1❌ NoBig data, log processing, data warehousing (sequential I/O).
Cold HDDsc1❌ NoInfrequently accessed archival data (lowest cost).

gp2 vs gp3 Volumes

gp2 links disk size with speed performance. gp3 decouples disk size and performance, giving lower costs.

9EBS Multi-Attach

EBS Multi-Attach allows attaching the same EBS volume to up to 16 EC2 instances simultaneously within the same Availability Zone.

Multi-Attach rules: Supported only on Provisioned IOPS SSDs (io1/io2) within the same Availability Zone. Max 16 servers.

10Amazon EFS

Amazon EFS stands for Elastic File System. It is a managed Network File System (NFS) for Linux servers. Unlike EBS, an EFS file system can be mounted by hundreds of EC2 instances simultaneously across multiple Availability Zones.

📁 Real-World Analogy: EFS is like a shared cloud folder (like Google Drive / shared network drive). Every team member (server) across different offices (AZs) can open, read, and edit files in the shared folder at the same time!
Amazon EFS works across multiple AZs simultaneously, providing shared access for Linux server fleets.

EFS Key Features

  • Linux Only: Uses POSIX file permissions. Not compatible with Windows OS.
  • Auto Scaling Capacity: Pay only for stored bytes; capacity grows and shrinks automatically.
  • Storage Tiers: Standard (frequent access), Infrequent Access (EFS-IA), and Archive tier to reduce storage costs by up to 90%.

11Amazon EFS Hands-On

  1. Go to EFS Console → Click Create File System → Select VPC.
  2. Mount EFS directly during EC2 server launch wizard.
  3. Create a file on Server A (in AZ-a): 
    echo "Hello AWS" > /mnt/efs/fs1/hello.txt
  4. Log into Server B (in AZ-b) and inspect the directory: 
    cat /mnt/efs/fs1/hello.txt
# Output -> Hello AWS

This demonstrates instant cross-AZ file sharing across Linux servers!

13Clean-Up Checklist

  1. Delete EFS File Systems.
  2. Terminate all running EC2 instances.
  3. Delete unattached EBS Volumes in "available" state.
  4. Delete saved EBS Snapshots.
  5. Delete non-default Security Groups.

📋 Cheat Sheet

Storage Decision Matrix

Storage NeedRecommended Service
Single EC2 virtual hard drive (persistent)EBS Volume
Shared network files across Linux servers in multiple AZsAmazon EFS
Maximum I/O speed, temporary scratchpad dataEC2 Instance Store
Clustered database shared volume (same AZ)EBS Multi-Attach (io1/io2)
Golden software server templateAMI

Key Numbers to Remember

  • EBS Multi-Attach: Max 16 instances, same AZ only.
  • gp3 Baseline: 3,000 IOPS / 125 MB/s (decoupled from disk size).
  • Snapshot Archive Tier recovery: 24 to 72 hours delay.

Mental Model Summary

EBS is your personal network drive locked to one AZ. Snapshots allow you to backup and move EBS data across AZs and Regions. AMIs store pre-configured operating system software templates. Instance Store provides top physical disk speed but erases data on server stop. EFS acts as a shared network drive across multiple AZs for Linux fleets.
