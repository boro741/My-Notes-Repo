1 EC2 Instance Metadata (IMDS)

IMDS (Instance Metadata Service) allows an EC2 instance to query information about itself without needing an IAM access key stored inside the server. The EC2 instance queries a special local link-local IP address:

http://169.254.169.254

Real-world Analogy Think of IMDS like an EC2 instance looking into a mirror in its room to check its own ID badge details (instance ID, private IP, public IP, and attached IAM role).
  • From this URL, an instance can fetch its hostname, public IP, private IP, and instance type.
  • It can also fetch temporary credentials for the IAM Role attached to the server (an IAM Role is like a temporary visitor pass with permissions).
  • You cannot see the full JSON security policy document attached to the role — only the temporary security credentials.
Important Difference Metadata = information about the server itself (IPs, role credentials). User Data = the startup shell script executed when the server first boots up. Both use 169.254.169.254.

IMDSv1 vs IMDSv2

IMDS VersionHow it WorksNotes
IMDSv1Directly query the metadata URL via simple GET requestSimpler, but vulnerable to SSRF security attacks
IMDSv22-step session token process: (1) Send PUT request to get a session token, (2) Pass that token in header X-aws-ec2-metadata-token when sending GETMore secure; default on Amazon Linux 2023 AMIs

IMDSv2 workflow: Request token using PUT → Receive token → Fetch metadata using GET with token header.

2 IMDS Hands On

  • When launching an EC2 instance, you can choose metadata options: V1 and V2 or V2 only.
  • Amazon Linux 2023 enforces V2 only by default.
Common Error On Amazon Linux 2023, attempting a direct IMDSv1 curl command returns 401 Unauthorized. You must use the 2-step IMDSv2 token flow instead.

Fetching Metadata via IMDSv2

  1. Generate a session token:
    TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" -H "X-aws-ec2-metadata-token-ttl-seconds: 21600")
  2. Fetch metadata using the token header:
    curl -H "X-aws-ec2-metadata-token: $TOKEN" http://169.254.169.254/latest/meta-data/
  3. Example paths: .../meta-data/local-ipv4 returns the private IP address.
  4. IAM credentials path: .../meta-data/iam/security-credentials/your-role-name returns temporary Access Key ID, Secret Access Key, and Session Token.
Good to Know You do not need to fetch IMDS credentials manually in application code. The AWS SDK and AWS CLI automatically call IMDS in the background to handle authentication.

3 AWS CLI Profiles

If you work across multiple AWS accounts (e.g. Development and Production), named profiles let you save separate sets of credentials locally on your laptop.

Real-world Analogy Profiles are like carrying multiple identity cards in your wallet for different offices (`[default]`, `[dev]`, `[prod]`). You pick which ID card to present when performing a task.

Managing Profiles

  • Default configuration lives in ~/.aws/credentials and ~/.aws/config.
  • Configure a new named profile:
    aws configure --profile my-dev-account
  • Run a CLI command using a specific profile:
    aws s3 ls --profile my-dev-account

4 AWS CLI with Multi-Factor Authentication (MFA)

To run AWS CLI commands with MFA security enabled, you generate temporary credentials using the AWS Security Token Service (STS) API call: sts get-session-token.

Exam Tip Remember the exact API name: STS GetSessionToken. You pass your MFA device ARN and the current 6-digit code. It returns temporary credentials (Access Key ID, Secret Access Key, and Session Token) valid for a short time.

Command Example

aws sts get-session-token --serial-number arn:aws:iam::123456789012:mfa/user-mfa --token-code 123456

Add the returned aws_session_token to your profile inside ~/.aws/credentials to execute secure CLI commands.

5 AWS SDK Overview

The AWS SDK (Software Development Kit) allows you to integrate AWS services directly into your application code (Java, Python, Node.js, Go, .NET, C++, etc.).

Real-world Analogy Using an SDK is like using a ready-made mobile banking app module inside your code, rather than having to write custom network socket code to talk to the bank's servers manually.

Fun Fact: The AWS CLI tool is written in Python and uses the official Python SDK (Boto3) under the hood!

6 Exponential Backoff & Service Quotas

AWS enforces two distinct limits to keep cloud services stable:

Limit TypeDescriptionExample
API Rate Limits (Throttling)Limits how many API requests per second you can sendGetObject on S3: 5,500 GETs/sec per prefix. Throttling error: 429 / SlowDown / ProvisionedThroughputExceeded
Service Quotas (Service Limits)Limits total resources running at once in an accountMaximum number of vCPUs or On-Demand EC2 instances allowed

Handling Throttling: Exponential Backoff

When an API request gets throttled, retry the request but double the wait time after each failed attempt (e.g. 1s → 2s → 4s → 8s → 16s).

Real-world Analogy If a friend's phone line is busy, you don't call every 1 second. You wait 1 minute, then 2 minutes, then 4 minutes so you don't block the network. That is exponential backoff.

Exponential backoff doubles the retry waiting time to give busy servers room to recover.

Exam Rule If you see "API throttling exception" on the exam, the solution is to implement exponential backoff. All AWS SDKs have this retry mechanism built in automatically.

7 AWS Signature v4 Signing (SigV4)

Every HTTP API request sent to AWS must be digitally signed with your secret credentials using the SigV4 (Signature Version 4) protocol so AWS can verify who sent the request.

Two Ways SigV4 Signatures Are Passed

Signing MethodHow Signature Is Sent
Authorization HeaderThe signature string is included inside the standard HTTP Authorization header (used by default by AWS CLI and SDKs).
Query String ParametersThe signature is attached directly to the URL as a query parameter (e.g. ?X-Amz-Signature=...). Used for temporary pre-signed S3 URLs.

✓ Cheat Sheet

Key Facts to Remember

  • IMDS base URL is 169.254.169.254. IMDSv2 uses a 2-step token-based PUT flow for better security.
  • IMDS lets an instance fetch metadata and temporary IAM Role credentials, but not the raw policy document.
  • Use aws configure --profile <name> to manage multiple AWS accounts locally.
  • Use STS GetSessionToken to generate temporary MFA-authenticated CLI credentials.
  • AWS SDKs allow calling AWS services programmatically inside application code. The CLI is built on the Python SDK (Boto3).
  • Handle API Throttling errors using Exponential Backoff (built into AWS SDKs).
  • AWS SigV4 signs API requests using either the HTTP Authorization header or URL query parameters (X-Amz-Signature).

Simple Mental Model

An EC2 server checks its mirror (IMDS at 169.254.169.254) to fetch its own identity and temporary IAM role pass. Developers manage multiple account keys using CLI profiles, execute MFA logins via STS, and write application code using SDKs. All requests to AWS are signed with SigV4 for security, and when AWS throttles busy applications, code backs off exponentially to keep connections running smoothly.
