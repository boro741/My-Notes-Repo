108VPC, Subnets, IGW and NAT

VPC (Virtual Private Cloud) = your own private network inside AWS, where you deploy resources. A VPC is a regional resource — two AWS Regions always have two separate VPCs.

Subnets partition your VPC's network, and each subnet lives in exactly one Availability Zone. There are two kinds:

  • Public subnet — accessible from (and can access) the internet
  • Private subnet — not accessible from the internet

Route tables define how traffic flows between subnets and to/from the internet.

A VPC spans a Region, and subnets are split across Availability Zones — each subnet is either public or private.
Default VPC: Every AWS Region has one created for you automatically — it only has public subnets (one per AZ), no private subnets. This is the VPC you've been using all along in this course for EC2 instances.

Internet Gateway (IGW) — what makes a subnet "public"

An Internet Gateway lives inside your VPC and lets VPC resources connect to the internet. A subnet is only "public" because it has a route in its route table pointing to the IGW.

NAT Gateway / NAT Instance — internet access for private subnets

A private subnet's instances might still need internet access (e.g. to download software updates) without being reachable from the internet. That's what a NAT Gateway (or NAT Instance) is for.

NAT GatewayNAT Instance
Managed byAWS (fully managed)You (self-managed EC2 instance)
Scaling / provisioningAutomaticManual
PurposeGive private subnet instances outbound internet access while staying unreachable from the internet
Private subnet → route to NAT Gateway (in the public subnet) → route to Internet Gateway → internet. Traffic only flows outbound; the internet can't initiate a connection back in.

109NACL, Security Groups, VPC Flow Logs

Two layers of network security guard traffic on its way to your EC2 instance:

Traffic hits the Network ACL first (subnet-wide firewall), then the Security Group (instance-level firewall), before reaching the EC2 instance.

Network ACL (NACL)

  • A firewall attached at the subnet level
  • Rules can allow AND deny traffic (explicit rules)
  • Rules only reference IP addresses
  • Stateless — you must explicitly allow both inbound and outbound traffic

Security Group

  • A firewall attached to an ENI or EC2 instance
  • Rules can only allow traffic (no explicit deny)
  • Rules can reference IP addresses or other security groups
  • Stateful — return traffic is automatically allowed, regardless of outbound rules
AspectSecurity GroupNetwork ACL
ScopeInstance / ENISubnet
Rule typesAllow onlyAllow and Deny
StateStateful (return traffic auto-allowed)Stateless (must allow both directions)
Can referenceIPs or other security groupsIP addresses only
Why you haven't touched NACLs in this course: the default NACL on a default VPC allows all inbound and outbound traffic — so security groups have been doing all the work so far.

VPC Flow Logs

Captures information about all IP traffic going through your network interfaces — at the VPC, subnet, or ENI level. Used to monitor and troubleshoot connectivity issues (e.g. "why can't this subnet reach the internet?").

  • Also captures traffic from AWS-managed resources: ELB, ElastiCache, RDS, Aurora, etc.
  • Can be sent to: Amazon S3, CloudWatch Logs, or Kinesis Data Firehose
Exam tip: Any question about "why is traffic being denied" or "how do I debug connectivity" → think VPC Flow Logs.

110VPC Peering, Endpoints, VPN, Direct Connect

VPC Peering

Connects two VPCs privately (using AWS's own network) so they behave as if they were one network. Requirements:

  • The two VPCs' CIDR (IP) ranges must not overlap
  • Peering is NOT transitive — each pair of VPCs that needs to talk needs its own peering connection
VPC peering is NOT transitive: to connect every VPC to every other VPC, you need a separate peering connection for each pair.

VPC Endpoints

Lets you connect to AWS services (like S3, DynamoDB, CloudWatch) using AWS's private network instead of the public internet — giving better security and lower latency. Important because all AWS services are technically public by default; an instance in a private subnet would otherwise need a NAT to reach them.

TypeUsed forScope
Endpoint GatewayS3 and DynamoDB onlyAttached to route table
Endpoint InterfaceMost other AWS services (e.g. CloudWatch)An ENI inside your subnet
A VPC Endpoint lets a private-subnet EC2 instance reach AWS services without going over the public internet.
Exam tip: Whenever a scenario asks for private access from your VPC to an AWS service → think VPC Endpoint.

Connecting on-premises to AWS: VPN vs Direct Connect

Site-to-Site VPNDirect Connect (DX)
PathOver the public internet (encrypted)Private, physical connection
Setup timeMinutesAt least a month
SecurityEncrypted tunnel over public internetPrivate line — doesn't touch the public internet
Best forQuick setup, temporary or lower-cost needsFast, secure, consistent-latency production links
Both connect your data center to AWS — VPN is fast to set up over the public internet; Direct Connect is private and physical but takes longer to provision.

112Three-Tier Architecture

All the VPC concepts above build toward a classic three-tier solution architecture — a pattern that shows up constantly in exam scenario questions.

Three tiers: public-facing ELB, private application EC2s (Auto Scaling Group across AZs), and a private data subnet with RDS + ElastiCache.
  1. Tier 1 — Web/Load Balancer: users query Route 53 (DNS) → reach the ELB, which sits in a public subnet since it must be internet-facing, spread across multiple AZs
  2. Tier 2 — Application: the ELB spreads traffic to EC2 instances in an Auto Scaling Group, deployed in private subnets (only reachable from the ELB, not the internet)
  3. Tier 3 — Data: a separate, deeper private "data" subnet holds Amazon RDS (read/write database) and ElastiCache (caches RDS data, or stores session data for the app tier)
Exam tip: This exact "ELB in public subnet → app EC2s in private subnet → database in an even more private data subnet" layout is a very common scenario question pattern.

The LAMP Stack on EC2

LAMP = a classic web stack you may see referenced in exam scenarios:

LetterComponentRole
LLinuxOperating system for the EC2 instance
AApacheWeb server, running on Linux/EC2
MMySQLDatabase (e.g. MySQL on RDS)
PPHPApplication logic that renders web pages

You can extend a LAMP stack with Redis/Memcached (via ElastiCache) for caching, and EBS volumes attached to EC2 for local application data/software storage.

WordPress on AWS (simplified)

WordPress uses the same two-tier idea (load balancer + application), but instances need to share uploaded images across the whole fleet. The natural fit: EFS (a shared network file system), since it creates ENIs in each AZ, letting every EC2 instance read/write the same shared files.

All EC2 instances behind the load balancer share the same uploaded images via EFS — every instance sees the same files.
Instructor's note: the full official AWS WordPress reference architecture includes NAT gateways, internet gateways, ASGs, Aurora, EFS, and more — by this point in the course, you should be able to understand nearly all of it (except CloudFront and S3, which come later).

Key facts to remember

  • One default VPC per Region, with only public subnets
  • Subnets = tied to one AZ; VPC = spans a whole Region
  • Security Groups are stateful; NACLs are stateless
  • VPC Peering is not transitive — connect every pair explicitly
  • VPC Endpoint Gateway = S3 & DynamoDB only; Endpoint Interface = everything else
  • VPN = fast setup, public internet, encrypted. Direct Connect = ~1 month setup, private physical line

Mental model recap

  • VPC = your private network in AWS. Subnets = zones within it, public or private.
  • IGW = the door to the internet for public subnets. NAT = a one-way door for private subnets.
  • NACL = the wall around the whole subnet. Security Group = the lock on each instance's own door.
  • The classic three-tier architecture (public ELB → private app EC2s → private data subnet) is the payoff for understanding all of this — and it shows up constantly on the exam.
