107VPC Fundamentals — Section Introduction

This section gives you a quick, simple overview of VPC (Virtual Private Cloud). For Solutions Architect or SysOps exams, VPC is a deep topic. But for the AWS Developer Associate exam, you only need to know high-level concepts because usually just 1 to 3 questions test this topic.

What you will learn in this section:

  • VPC & Subnets
  • Internet Gateways & NAT Gateways
  • Security Groups & Network ACLs (NACL)
  • VPC Flow Logs
  • VPC Peering & VPC Endpoints
  • Site-to-Site VPN & Direct Connect
Relax and learn the basics: Focus on understanding what each service does. You do not need to memorize deep network setup steps right now.

108VPC, Subnets, IGW and NAT

VPC (Virtual Private Cloud) = Your own isolated private network inside AWS where you set up your cloud servers and services.

Real-world Analogy: Think of a VPC like a gated housing society / apartment complex built just for you in the cloud. It isolates your private area from the outside world.

A VPC is a regional resource. This means two different AWS Regions (like Mumbai and Singapore) will always have separate VPCs.

Subnets divide your VPC network into smaller sections (like dividing your housing society into different apartment blocks). Each subnet belongs to exactly one Availability Zone (AZ). There are two types of subnets:

  • Public Subnet: Connected to the internet (like the society visitor parking area or reception gate). Anyone from the internet can reach resources here.
  • Private Subnet: Hidden from the internet (like private family flats inside the society). Internet users cannot directly connect to resources here.

Route tables act like road map signs inside your VPC, telling network traffic where to go.

A VPC covers a whole AWS Region. Subnets sit inside specific Availability Zones and are marked as public or private.
Default VPC: AWS automatically creates one default VPC in every Region. This default VPC contains only public subnets (one subnet per AZ). You have been using this default VPC to launch EC2 instances in this course.

Internet Gateway (IGW) — Main Entrance to the Internet

An Internet Gateway (IGW) is the main door attached to your VPC that connects it to the public internet. A subnet becomes "public" only when its route table points directly to the IGW.

NAT Gateway / NAT Instance — Outbound Internet for Private Subnets

Servers inside a private subnet (like database servers) often need to download software updates from the internet, but outsiders should never reach them directly. A NAT Gateway (or NAT Instance) allows this one-way communication.

Real-world Analogy: Think of a NAT Gateway like ordering food online at home. The delivery person brings your package inside because you asked for it (outbound request), but a total stranger cannot walk into your home uninvited (inbound request blocked).
FeatureNAT GatewayNAT Instance
Managed byAWS handles everything (fully managed)You handle it (you manage an EC2 instance)
ScalingScales automaticallyYou must upgrade or scale manually
Main PurposeAllows private subnet servers to download updates from the internet while keeping them safe from incoming internet attacks
Traffic flow: Private Subnet → NAT Gateway (placed in Public Subnet) → Internet Gateway → Internet. Only outbound traffic is allowed.

109NACL, Security Groups, VPC Flow Logs

AWS protects network traffic reaching your EC2 server using two security barriers:

Incoming traffic must pass through the Network ACL (subnet level) first, and then the Security Group (instance level) before hitting your EC2 server.

Network ACL (NACL) — The Main Gate Security Watchman

Real-world Analogy: A NACL is like the security gatekeeper at the main colony/society gate.
  • Operates at the subnet level.
  • Can have both Allow AND Deny rules (you can explicitly block specific dangerous IP addresses).
  • Rules filter traffic based only on IP addresses.
  • Stateless: You must create rules for both incoming (inbound) and outgoing (outbound) traffic separately.

Security Group — The Personal House Door Security Guard

Real-world Analogy: A Security Group is like a security guard standing right outside your private apartment door.
  • Operates at the EC2 instance level (or network card ENI level).
  • Supports ALLOW rules only (no explicit deny rules).
  • Can filter by IP addresses or other Security Groups.
  • Stateful: If incoming traffic is allowed in, the response traffic is automatically allowed out.
FeatureSecurity GroupNetwork ACL (NACL)
Where it worksInstance / Network Interface (ENI) levelSubnet level
Rule types allowedAllow rules onlyBoth Allow and Deny rules
State memoryStateful (reply traffic is auto-approved)Stateless (must configure inbound and outbound separately)
Rules can targetIP addresses or other Security GroupsIP addresses only
Why NACL feels new: The default NACL in AWS automatically allows all incoming and outgoing traffic. So until now, your Security Groups have been handling all filtering.

VPC Flow Logs — CCTV Camera for Network Traffic

VPC Flow Logs record details about all network traffic passing through your VPC, subnets, or EC2 network cards. It helps you check and solve connection problems (for example, finding out why traffic is being blocked).

Real-world Analogy: Think of VPC Flow Logs like CCTV cameras recording entry logs to monitor who entered and left the building.
  • Tracks traffic for AWS services like ELB (Load Balancers), RDS databases, and ElastiCache.
  • Logs can be saved to: Amazon S3, CloudWatch Logs, or Kinesis Data Firehose.
Exam Tip: If an exam question asks how to debug network blocks or inspect denied traffic, choose VPC Flow Logs.

110VPC Peering, Endpoints, VPN, Direct Connect

VPC Peering — Connecting Two VPCs Privately

VPC Peering connects two separate VPCs over AWS's private network so servers in both VPCs can talk to each other as if they were in the same network.

Real-world Analogy: Like building a private footbridge between two neighboring housing societies so residents can cross over directly without walking on the public main road.
  • The two VPCs must not have overlapping IP (CIDR) ranges.
  • Peering is NOT transitive: If VPC A connects to VPC B, and VPC B connects to VPC C, VPC A cannot talk to VPC C automatically. You must create a direct link between A and C.
VPC Peering is non-transitive. To connect every VPC together, each pair needs its own separate peering setup.

VPC Endpoints — Private Access to AWS Services

A VPC Endpoint lets servers in your private subnet connect to AWS services (like S3 or DynamoDB) using AWS's private internal network instead of going out to the public internet. This provides faster speeds and better security.

Endpoint TypeSupported AWS ServicesHow it attaches
Gateway EndpointAmazon S3 and DynamoDB onlyAdded directly to your route table
Interface EndpointMost other AWS services (like CloudWatch, EC2 API)Uses a private network card (ENI) inside your subnet
With a VPC Endpoint, your private EC2 instance accesses AWS services safely without going over the public internet.
Exam Tip: Whenever a question asks how to connect a private subnet to AWS services without using the public internet, choose VPC Endpoints.

Connecting Your Office Data Center to AWS: Site-to-Site VPN vs Direct Connect

FeatureSite-to-Site VPNAWS Direct Connect (DX)
Network PathRuns over the public internet using encryptionDedicated private physical cable line
Setup TimeTakes just a few minutesTakes about 1 month to set up physically
Security LevelEncrypted tunnel over the internetPrivate cable line (never touches the public internet)
Best Used ForQuick setup, short-term needs, lower costHigh-speed, reliable production connections with stable speed
VPN provides quick encrypted access over the internet. Direct Connect gives a private physical cable for maximum performance.

112Three-Tier Solution Architecture

All these VPC pieces come together to form the standard 3-Tier Architecture — a core design pattern tested heavily in AWS exams.

3-Tier Design: Public Load Balancer → Private Application Servers → Private Database & Cache Layer.
  1. Tier 1 — Web / Load Balancer: Users connect via Route 53 (DNS — phonebook of the internet) to an Elastic Load Balancer (ELB) in a Public Subnet across multiple AZs.
  2. Tier 2 — Application Tier: The ELB routes traffic to application EC2 servers running inside an Auto Scaling Group in Private Subnets. These cannot be accessed directly from the internet.
  3. Tier 3 — Data Tier: A separate, highly protected Private Data Subnet houses your database (Amazon RDS) and in-memory cache (ElastiCache).
Exam Tip: "Public ELB → Private App EC2s → Private Database Subnet" is the most common architectural layout seen in scenario questions.

The LAMP Stack on EC2

LAMP is a classic web development stack:

WordPress on AWS (Simplified)

WordPress uses an app tier and database tier. Since multiple WordPress servers need to share uploaded photos and media files, they use Amazon EFS (a shared network file system like a shared Google Drive for EC2s) attached across all Availability Zones.

All WordPress EC2 servers share uploaded images from a central Amazon EFS file system.

Important Facts to Remember

  • Every Region comes with one default VPC containing only public subnets.
  • Subnets live inside a single Availability Zone (AZ). A VPC spans the whole Region.
  • Security Groups are stateful (auto-approves reply traffic). NACLs are stateless.
  • VPC Peering is not transitive. Connect each pair directly.
  • Gateway Endpoints are for S3 & DynamoDB. Interface Endpoints are for most other services.
  • VPN is fast to set up over internet. Direct Connect takes ~1 month to lay a private physical cable.

Simple Mental Model

  • VPC = Gated housing society in the cloud. Subnets = Apartment blocks inside it.
  • IGW = Society main entrance gate. NAT Gateway = One-way delivery slot for private flats.
  • NACL = Security gatekeeper at the main colony gate. Security Group = Guard right outside your apartment door.
  • 3-Tier Architecture = Public Load Balancer → Private Application Servers → Private Database Subnet.
