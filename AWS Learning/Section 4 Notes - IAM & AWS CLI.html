11IAM Introduction: Users, Groups, Policies

IAM stands for Identity and Access Management. It is the security gatekeeper for your AWS account. IAM is a global service — this means the users, groups, and permissions you create apply everywhere across the world, without picking a specific AWS Region (like Mumbai or N. Virginia).

🏢 Real-World Analogy: Think of IAM like the security administration of a large corporate office building. It controls who can enter the building (Authentication) and which specific rooms or floors they can visit (Authorization).

When you create a brand-new AWS account, you start with a Root User. The Root User has complete control over everything. You should only use the Root User once to set up your account. After that, lock it away safely and create individual IAM Users for daily work. Rule of thumb: One IAM user = One real person in your company (e.g., Alice, Bob, or Rahul).

Users and Groups

  • IAM Groups are collections of users (e.g., a "Developers" group or an "Admins" group) that make assigning permissions fast and easy.
  • Groups only hold users — you can never put a group inside another group.
  • A user does not have to join a group, but putting users in groups is the best security practice.
  • A user can belong to multiple groups at the same time (e.g., Charles can be in both "Developers" and "Audit Team").
Groups only contain users. A user (like Charles or David) can belong to more than one group at the same time; Fred belongs to none.

IAM Policies — How Permissions Are Granted

Users and groups get permissions through IAM Policies. A policy is a standard JSON document (a simple text-based rulebook) that defines what actions a user or group can or cannot perform on AWS.

Principle of Least Privilege (Security Rule): Never give a user more permissions than they need for their job. Giving full admin access to everyone creates high security risks and accidental costs — for instance, a fresh hire could accidentally delete production databases or start expensive servers!

12-13Users & Groups Hands-On + Multi-Session Sign-In

Steps to Create an IAM User

  1. Open the IAM Console → Click Users → Click Create user (e.g., username Stephane), and check the box for AWS Management Console access.
  2. Select "I want to create an IAM user" (this is traditional IAM, which is tested in the AWS CCP exam).
  3. Set up a password: For a teammate, auto-generate a password and check "User must create a new password at next sign-in". For personal testing, pick a custom password.
  4. Set permissions: Instead of attaching permissions directly to the user, click Add user to group and attach a group (e.g., an admin group with AdministratorAccess policy).
  5. Tags (optional key-value pairs like Department = Engineering) can be attached to help organize and track resources.

After creation, the user's permissions summary will show that access is inherited from the group. Grouping users keeps permissions neat and easy to audit.

Signing In as an IAM User

  • AWS provides a unique Sign-in URL containing your 12-digit Account ID.
  • You can create a custom Account Alias (e.g., my-company-aws) to replace the ugly ID number with a friendly URL link.
  • To stay logged into both your Root account and an IAM User simultaneously, use an Incognito / Private Browser Window.
Important Warning: Always safeguard your credentials. If you get locked out of both your Root user and Admin IAM user, recovery can be very difficult.

Multi-Session Sign-In (Console Feature)

AWS allows multi-session support in the console. You can switch between or stay logged into multiple AWS accounts (Root, IAM user 1, IAM user 2) inside separate tabs in the same web browser window without getting logged out.

14IAM Policies (Structure)

Where you attach an IAM Policy determines who gets affected:

  • Group Level Policy: Applies to every user inside that group automatically.
  • Inline / User Policy: Attached directly to one specific user.
  • Combined Permissions: If a user belongs to multiple groups and has an inline policy, AWS simply combines all allowed permissions together.

Structure of an IAM Policy Document

Every IAM policy contains Version + optional Id + one or more Statements. Key statement fields: Effect, Principal, Action, and Resource.

An IAM Policy JSON is built from these core elements:

  • Version: The policy language version (always use "2012-10-17").
  • Id: An optional identifier for the policy.
  • Statement: The main body, containing one or more rule blocks:
    • Sid: An optional statement ID for labeling the block.
    • Effect: Set to either "Allow" or "Deny".
    • Principal: The account, user, or role this policy applies to (required in resource-based policies).
    • Action: The specific list of AWS API actions allowed or denied (e.g., s3:GetObject, iam:ListUsers).
    • Resource: The specific AWS resources being targeted (e.g., a specific S3 bucket or "*" for all resources).
    • Condition (Optional): Rules specifying when the policy applies (e.g., only when MFA is active or from a specific IP address).
Exam Tip: Memorize the key statement fields: Effect, Principal, Action, and Resource. These four fields define who can perform what action on which resource!

15IAM Policies Hands-On

Testing Permissions in Practice

  1. Removed user Stephane from the admin group → all administrator privileges disappeared instantly.
  2. Refreshed the IAM page → received an Access Denied error for iam:ListUsers, proving permissions are enforced immediately.
  3. Attached the AWS-managed policy IAMReadOnlyAccess directly to the user → user could view IAM resources again, but attempting to create a new user resulted in an Access Denied error.
  4. Re-added user to the admin group to restore full admin access.

Understanding AWS Managed Policies

AdministratorAccessAction: *, Resource: * — allows every action on every AWS resource.
IAMReadOnlyAccessUses wildcards like Get* and List* — allows reading data without making changes.

You can also use the Visual Editor in the AWS Console to pick services and tick actions visually. AWS automatically generates the clean JSON policy code for you!

Troubleshooting Tip: If a user cannot perform an action, check all permission sources — individual user policies, group policies, and role policies.

16IAM MFA Overview

To secure your AWS account, use two defense mechanisms:

1. Strong Password Policy

  • Set minimum password length and enforce character requirements (uppercase, lowercase, numbers, non-alphanumeric symbols).
  • Allow or block users from changing their own passwords.
  • Force password expiration (e.g., mandatory reset every 90 days).
  • Prevent password reuse.

2. Multi-Factor Authentication (MFA)

MFA requires two factors to log in: something you know (your password) + something you have (your phone or physical security key).

💳 Real-World Analogy: MFA is like withdrawing money from an ATM. You need your physical ATM card (something you have) and your secret 4-digit PIN (something you know). Knowing the PIN alone is useless without the card!
MFA does not replace your password — it adds an essential physical layer of security on top of it.

17IAM MFA Hands-On

  1. Setting Password Policy: Account Settings → Password Policy → choose AWS defaults or set custom rules (length, expiration, character rules).
  2. Enabling MFA on Root User: Click Account Name → Security Credentials → Assign MFA Device.
  3. Name the device (e.g., "My iPhone"), select Authenticator app.
  4. Scan the displayed QR code using your phone app (Google Authenticator or Authy).
  5. Enter two consecutive 6-digit codes from the app to sync the device, then click Add MFA.
Important Warning: Keep your MFA device safe! If you lose your phone/device tied to MFA, you could get locked out of your AWS account.

18Access Keys, CLI & SDK

There are 3 ways to interact with AWS services:

All three options call the exact same underlying AWS APIs. They only differ in how you authenticate and where you run them.
  • AWS Management Console: Web browser interface using username, password, and MFA.
  • AWS CLI (Command Line Interface): Terminal tool that lets you control AWS services using commands and scripts. Every CLI command starts with aws.
  • AWS SDK (Software Development Kit): Code libraries (Python, Java, JavaScript, C++, Node.js, etc.) that let software applications call AWS APIs programmatically.
  • Access Keys: Created in the IAM Console for CLI and SDK access. Made of two parts:
    • Access Key ID: Works like a username.
    • Secret Access Key: Works like a password. Never share this key with anyone!
Fact: The AWS CLI itself is written in Python and uses Boto3 (the AWS SDK for Python)!

19-21AWS CLI Setup (Windows / Mac / Linux)

Installing the AWS CLI v2 is straightforward on all operating systems:

On macOS: Download the official .pkg installer, follow the wizard instructions, open your Terminal, and verify installation with:

aws --version

A successful install outputs something like aws-cli/2.x.x.

Installation Rule: Download official installers from AWS documentation and always verify using aws --version in your terminal.

22AWS CLI Hands-On

  1. Generate Access Keys: User → Security Credentials → Create access key.
  2. Download or copy your Secret Access Key immediately — AWS displays it only once!
  3. Configure your local CLI: Open your terminal, run aws configure, and input your Access Key ID, Secret Access Key, default region (e.g., ap-south-1 for Mumbai or eu-west-1), and default output format (JSON).
  4. Test CLI access: Run aws iam list-users to display users in JSON format.
Same Permissions Everywhere: The CLI respects IAM policies completely. If an IAM user lacks permissions in the web console, running the command via CLI will fail with the exact same Access Denied error.

23AWS CloudShell

AWS CloudShell is a free, browser-based terminal built right inside the AWS Management Console (accessible via the prompt icon in the top header bar).

  • No local installation needed — AWS CLI comes pre-installed and automatically logged in as your current user session.
  • Sets your current AWS Console Region as the default region automatically.
  • Includes persistent storage (files created in CloudShell remain saved between sessions).
  • Supports uploading/downloading files and multiple tab layouts.
Summary: CloudShell is a zero-setup browser terminal. If it is available in your selected region, you can use it instantly without setting up a local terminal!

24IAM Roles for AWS Services

Just like real people need IAM Users to access AWS, AWS services (like EC2 servers or Lambda functions) need permission to access other AWS services. We give permissions to AWS services using IAM Roles.

🪪 Real-World Analogy: An IAM Role is like a temporary visitor pass or entry badge. When a contractor enters an office, they receive a temporary badge giving them access to specific rooms for a limited time. They do not get a permanent employee ID card!
The EC2 server assumes the IAM Role, gaining temporary permissions to call AWS APIs safely without storing access keys.

Common examples include EC2 Instance Roles and Lambda Function Roles.

25IAM Roles Hands-On

  1. Go to IAM Console → Click Roles → Click Create role.
  2. Select AWS service as the trusted entity, and pick EC2.
  3. Attach the required policy (e.g., IAMReadOnlyAccess).
  4. Name the role (e.g., DemoRoleForEC2) and click Create.

Once created, this role can be assigned to an EC2 instance so the server can talk to AWS APIs securely without embedding hardcoded access keys in application code!

26IAM Security Tools

Security ToolScopeFunction
IAM Credentials ReportAccount-wideDownloads a CSV list of all account users and their security details (passwords, MFA, keys).
IAM Access AdvisorPer-user levelShows which AWS service permissions a user has, and when they last actually accessed each service.
Why Access Advisor is Useful: Access Advisor enforces the Principle of Least Privilege. If a user has permission to 20 services but only uses 2, you can safely remove the unused 18 permissions!

27IAM Security Tools Hands-On

Credentials Report

Go to IAM → Click Credential report → Click Download Report. This generates a CSV spreadsheet detailing every user's creation date, password status, MFA status, access key rotation dates, and last activity time.

Access Advisor

Select any IAM User → Click the Access Advisor tab. It lists every AWS service allowed for that user alongside the last accessed timestamp (e.g., "Accessed 2 days ago" vs "Never accessed"). Use this data to trim unnecessary permissions.

28IAM Best Practices

  • Do not use the Root Account for daily tasks — use it only for initial account setup.
  • One IAM User per real person — never share account login credentials.
  • Assign users to Groups and manage permissions at the Group level.
  • Enforce a strong password policy and mandatory MFA.
  • Use IAM Roles to grant permissions to AWS services (like EC2 instances).
  • Keep Access Keys secret and rotate them periodically.
  • Audit permissions regularly using IAM Credentials Report and Access Advisor.
Critical Rule: Never leak or commit Access Keys or passwords into public code repositories like GitHub!

29Shared Responsibility Model for IAM

AWS splits security responsibilities between AWS and the Customer:

AWS secures the cloud infrastructure (Security OF the Cloud). You secure your IAM setup and user access (Security IN the Cloud).

📋 Cheat Sheet

Core Building Blocks

ConceptSimple Explanation
IAM UserOne physical person; logs in with password or access keys.
IAM GroupCollection of users only; inherits permissions as a team.
IAM PolicyJSON rulebook defining allowed/denied actions.
IAM RoleTemporary identity pass for AWS services (EC2, Lambda).
Access KeysAccess Key ID + Secret Access Key for CLI and SDK access.

Key Exam Facts to Remember

  • IAM is a global service (not region-bound).
  • Groups contain only users, never other groups.
  • IAM Policy structure: Version + Statement(s) (containing Effect, Principal, Action, Resource, Condition).
  • Least Privilege: Grant only minimum required permissions.
  • MFA = Password (something you know) + Device (something you have).
  • CloudShell = Free, zero-setup browser terminal built into the AWS Console.
  • Audit Tools: IAM Credentials Report (CSV for account users) and IAM Access Advisor (service last-accessed dates).

Mental Model Summary

Root account is for initial account setup only. Day-to-day work is done using IAM Users grouped into Teams. IAM Policies define exact permissions using JSON rules. IAM Roles act as temporary entry passes for AWS services. MFA protects human logins, while Access Keys protect CLI/SDK access. Audit tools keep your account secure by identifying unused permissions.
